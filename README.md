# Emby-go

一个用 **Go** 重写的、兼容 **Emby API** 的轻量媒体库服务端，面向 **AV / FC2 类 NFO + `.strm` 媒体库**（海报墙浏览走 Emby 客户端）。

- 元数据真源 = **现成 NFO**（`<title>/<genre>/<studio>/<actor>/<set>` 等），不内置刮削器
- 媒体只支持 `http(s)://` 的 `.strm`；播放走 **302 直拉**（服务端零带宽，不转码）
- 单二进制、单端口，Redis 为必选缓存后端；内置深色 Web 管理后台
- 兼容端点覆盖：认证、媒体库/影片墙、详情、图片、合集(BoxSet)、进度/续播、搜索/过滤等 Emby 客户端浏览主链路

## 快速开始

### 构建

```bash
go build -o metatube ./cmd/metatube
```

### 运行

```bash
# 默认读取 ./config.yaml；也可用 -c 指定其它配置文件
./metatube
./metatube -c /etc/emby-go/config.yaml
./metatube -version
```

`config.yaml` 属本地私人配置（已在 .gitignore 中，不入库）；首次使用复制示例并修改：

```bash
cp config.example.yaml config.yaml
```

监听端口在配置文件的 `port`（或 `listen`）中设置，命令行只负责选择配置文件。浏览器打开 `http://127.0.0.1:<port>` 走初始化向导（创建管理员账号）。

### 目录约定

每个条目形如：

```
ABF-018/
├── ABF-018.strm        # 内容为 http(s)://... 一行
├── ABF-018.nfo         # Kodi/Emby 风格元数据
├── poster.jpg          # 可选：主海报（也认 folder.jpg/cover.jpg）
├── thumb.jpg           # 可选：宽图（Thumb，也认 landscape.jpg）
├── fanart.jpg          # 可选：背景图（Backdrop）
└── extrafanart/        # 可选：多张剧照，按数字顺序索引
    ├── fanart1.jpg
    ├── fanart2.jpg
    └── fanart10.jpg
```

扫描时 `.strm` 按 scheme 分类：`http/https` + NFO → 可播放；`http(s)` 无 NFO → 待补录；`ed2k` 等其它 scheme → 不兼容（不进 Emby）。

扫描**不做图片格式转换**，直接引用目录里已有的图片（`webp`/`jpg`/`jpeg`/`png`/`gif`/`tbn`）。媒体库封面优先取**库根目录**下 `poster`→`folder`→`cover`→`default` 任一命名的图片（`cover.webp` 同样适用）；没有则借用库内最近入库影片的宽图/海报。

影片本地图片参考 [Emby 电影图片命名规则](https://emby.media/support/articles/Movie-Naming.html#video-images)：海报支持影片同名图及 `-poster`/`-cover`/`-default`/`-movie`，也认目录公共海报；宽图依次识别影片名 `-thumb`/`-landscape`、`thumb`/`landscape`。背景图识别 `backdrop`/`backdropX`、`fanart`/`fanart-X`、`background`/`background-X`、`art`/`art-X`，以及 `extrafanart/fanartX`（X 为数字）。保留服务生成的影片专属海报和背景图优先级；专属背景图不会混入目录公共背景，但仍包含 `extrafanart`。

多张背景图通过 `BackdropImageTags`、`GET /Items/{id}/Images` 的 `ImageIndex` 及 `GET /Items/{id}/Images/Backdrop/{index}` 提供给客户端，编号从 0 开始；管理端详情抽屉也展示剧照网格，可点击查看原图。图片与 `extrafanart` 目录的增删会触发父影片目录局部刷新。旧数据库自动补列，升级后进行一次增量扫描即可补齐图片，无需清库。

### 实时监听与局部刷新

服务默认启用媒体库监听，不需要点击扫描。Windows 使用 `ReadDirectoryChangesW` 原生递归通知，避免逐层打开目录句柄导致父目录无法移动；其他平台使用 fsnotify 并自动登记新增子目录。

- 启动服务、添加媒体库或恢复失联目录时，先做一次增量对账，补齐停机期间的变化。
- 正常文件事件默认等待 **1 秒静默期**，同一文件的重复通知合并；连续事件最多等待 **5 秒**便提交一批，防止一直不刷新。
- `.strm` / NFO 变化只刷新对应影片或 CD 分组；海报、背景图、宽图变化只刷新同目录影片；目录移入、移出或重命名只处理对应子树，不因单文件更新重新遍历整库。
- 文件事件是显式更新信号，因此即使写入工具保留文件大小和修改时间，相关影片也会重新读取。扫描期间的新事件继续排队；探测、刮削或手动扫描占用 NFO 通道时保留事件并重试。
- 删除媒体库会停止对应监听，退出服务会释放监听句柄。管理端「任务」页显示「实时局部刷新」，扫描进度接口返回本轮统计。
- 目录不可用或读取失败时保护已有索引。根目录失联后会尝试恢复；事件溢出时重新登记监听并做增量对账，积压超过 4096 个路径时合并为一次增量对账，避免静默漏更新。

### 兼容模式（30 秒轮询）

群晖系统、SMB/NFS 等远程文件系统挂载，以及出现「监控不工作」问题时，可以改用兼容模式，不依赖操作系统文件通知。在 `config.yaml` 中设置并重启服务：

```yaml
disable_library_monitor: false
library_monitor_mode: polling
```

- `realtime` 为默认实时监听模式；`polling` 为兼容模式，二者择一运行。`disable_library_monitor: true` 会关闭两种模式的自动监控。
- 启动时建立文件树快照并做一次增量对账；随后每 **30 秒**遍历目录，比较相关文件的路径、大小、纳秒修改时间和文件模式。检查串行执行，不重叠运行。
- 检测到差异后复用事件合并、防抖、繁忙重试和局部刷新；未变化时不解析 NFO、不写入影片索引、不刷新缓存。管理端任务显示「兼容模式局部刷新」。
- 文件新增、修改、删除及目录移动、重命名会在后续检查中同步；遍历失败时保留上一次完整快照和已有索引，恢复后继续比较，避免把读取失败当作删除。
- 兼容模式每轮仍需遍历文件树，有额外目录 I/O 和快照内存开销。通常在下个 30 秒检查周期加防抖时间后刷新，实际耗时还受目录规模、远程 I/O 和任务排队影响。两次检查之间发生又撤销的变化，或同时保留大小、修改时间及文件模式的内容替换，无法通过属性比较识别，可手动全量重建。

建议保留 `scan` 计划任务作为停机、挂载异常和漏事件的兜底。远程挂载的属性缓存可能额外延迟变化可见性；兼容模式提高通知兼容性，但不能消除挂载本身的读取或缓存问题。

### 增量扫描与全量重建

- **普通扫描默认增量**：顶部「开始扫描」、媒体库「增量扫描」、`POST /api/admin/scan` 及计划任务 `scan` 都只重新处理新增或变化的影片；`library_id` 可限定媒体库，不传则检查全部媒体库。
- **变化范围**：检查 `.strm`、同名 NFO、CD 分组的回退 NFO、当前使用的海报/背景/宽图，以及 CD 分段的新增、修改、删除。按路径、大小、纳秒修改时间和文件模式生成指纹，持久化在 SQLite；重启后仍可跳过未变化项。
- **首次建立基线**：升级后的第一次扫描会处理现有条目以建立指纹，以后未变化项不重读 NFO、不重写影片/演员索引，也不改变影片更新时间；完全无变化时不刷新列表缓存版本。
- **删除与故障**：成功扫描后同步清理磁盘上已删除/移动的源文件索引。媒体库根目录不可用或目录遍历失败时停止扫描、不清理；单条读取失败保留旧索引、跳过本轮删除清理，后续扫描重试。
- **全量重建保留**：总览「全量重建索引」、`POST /api/admin/reindex` 和计划任务 `reindex` 强制重读全部媒体库，忽略旧指纹，并重新建立基线；不需要先删库。
- **进度与结果**：返回并展示 `added`（新增）、`updated`（更新）、`skipped`（未变化）、`deleted`（删除）及 `failed`（失败）。原有 `success` / `pending` / `incompatible` 统计本轮实际处理的条目，不包含跳过项。

手动／定时增量扫描仍会遍历目录并检查文件属性，与实时监听触发的局部刷新不同。如果文件变化没有产生监听事件，且外部工具同时保留了文件大小和修改时间，属性指纹不能识别这种内容替换，请执行全量重建。

### 扫描性能与写入安全

- 扫描按最多 **100 部影片一批**写入 SQLite；批次内影片、演员关系、相似特征和扫描指纹一起提交，特征只计算一次。批次失败会整体回滚，未提交条目不会计入新增／更新成功数。
- STRM/NFO 读取和解析在数据库事务外进行；批次等待超过约 **500 毫秒**时，在后续条目处理完成后提前提交，避免少量变更长时间不入库。该间隔不是远程文件读取的超时时间。
- 图片选择结果复用于入库，已取得的图片属性复用于本次指纹；同目录共享本轮图片名称与属性快照，每部影片分别选取专属图片。更新后的稳定性复核使用新查询；小目录重新读取清单，大目录查询图片候选，并在批次写入前复核图片清单（含 `extrafanart`），变化的条目不保存成功指纹。快照不跨扫描保留。
- 单文件局部刷新先按影片/CD 分组过滤，再取得 STRM 属性，并复用目录遍历取得的图片名称。指纹查询按源文件前缀缩小返回范围，仍按精确分组筛选；Unicode 文件名和大批量事件回退目录查询，保留 CD 删除与主段切换语义。影片专属图片事件只刷新所属影片，目录公共图片事件刷新同目录影片。
- 批次复用演员写入语句，演员关系不变时不重建关系；相似特征直接从已解析元数据生成，与普通更新共用规则，特征不变时不重写。
- 目录遍历使用 `WalkDir`，仅对需要的 STRM 取得完整属性。扫描仍检查读取前后的依赖指纹；不稳定条目不保存成功指纹，下次扫描会重新处理。本地图片依赖升级为 `v2` 指纹，第一次增量扫描会重读存量条目，补齐宽图和多张背景图，此后恢复未变化项跳过；无需清库。
- 全量重建仍强制重读 NFO，不通过跳过解析伪装提速。数据库保持原有 WAL 与持久化设置，没有通过关闭同步写入降低安全性。

可用 `go test ./internal/scanner -run '^$' -bench '^BenchmarkLibraryScan$' -benchtime=3x` 比较首次扫描、全量重建和无变化增量扫描，覆盖逐影片目录与单个大目录两种布局。基准使用本地合成文件，不能直接代表 SMB/NFS 的耗时。

### 缓存范围与统计

- Redis 缓存影片列表、详情、分类、相似影片、媒体库封面及鉴权结果。管理端媒体墙列表缓存 **5 秒**；Emby 列表 **15 秒**、详情 **1 分钟**、分类 **30 秒**、相似影片 **20 秒**。图片缩略图与 NFO 流信息仍使用进程内缓存，避免逐张图片访问 Redis。
- 局部更新只推进受影响影片的详情版本和对应媒体库的列表版本；跨库列表、全局分类与相似结果随全局版本更新。整库扫描有变化时保守失效该库的详情及磁盘依赖；无变化扫描保留缓存。共享演员头像和头像目录设置变更会失效共享结果。
- 文件事件按路径或子树失效图片标签、NFO 与缩略图；ImageTag 与 ETag 同时包含修改时间和磁盘版本，即使写入工具保留修改时间，客户端也会重新取图。正在加载的旧响应只能写入旧版本，不能覆盖新缓存。
- 影片收藏、已看与停止播放会刷新相关详情和列表；用户状态与媒体元数据分别计版本，播放心跳只刷新单部详情，保留图片路径缓存，旧详情按 1 分钟 TTL 过期。列表进度按短缓存更新，管理端最多约 5 秒、Emby 列表最多约 15 秒。
- 常见列表、详情、分类、相似影片及封面请求发生同键并发未命中时，共享一次查询和响应生成；失败结果不缓存，等待者可随请求取消退出。合并发生在当前进程内。
- 缓存失效使用版本键；旧响应按 TTL 自然过期，不遍历删除 Redis 键，也不清除登录令牌或 API Key 缓存。响应键按当前进程分区，重启后重新建立响应缓存；SQLite 仍是持久真源。
- 管理端设置页显示响应缓存命中率和合并加载次数；`GET /api/admin/settings` 的 `cache_stats` 按类别提供 `hits`、`misses`、`loads`、`shared`、`load_errors` 与累计 `load_milliseconds`。统计自本次启动开始，不包含进程内图片/NFO 缓存。

### 刮削与编辑安全

- 新刮削及上传的图片使用影片文件名前缀，如 `ABF-018-poster.webp`、`ABF-018-fanart.webp`、`ABF-018-landscape.webp`。扫描优先使用影片专属图，旧的目录公共图继续作为回退；只补缺失模式保留已有图片。
- 批量刮削、扫描、探测、头像任务及单条补录/编辑/重读/上传/探测共用互斥通道。占用期间其他修改返回 409；同类型的独立请求也不能重入。
- 批量刮削取消或熔断后，仍会在释放通道前刷新成功落盘的影片，按媒体库及目录合并局部刷新。影片按批取回，媒体库信息复用，刷新前后各统一失效一次去重的磁盘路径，包含新旧图片依赖；刷新失败与原始任务错误一起返回。
- 请求日志隐藏 URL 和头中的令牌、API Key、Cookie 等凭据；debug 记录脱敏请求头，不记录请求正文，不影响实际鉴权与参数读取。

### 多分段（CD1/CD2）

同目录、同文件基名、末尾带 `-CD<数字>` 的 `.strm` 会被归为**一部逻辑影片**（对齐 Emby stacking 语义）：

```
Split/
├── Split-CD1.strm      # 主段（必须存在 CD1）
├── Split-CD1.nfo       # 主段 NFO 为元数据真源
├── Split-CD2.strm      # CD2+ 作为 AdditionalParts
└── Split-CD3.strm
```

- CD1 作为主影片进列表，`PartCount=CD 数`；CD2/CD3…（任意段数）不重复占列表位。
- 重扫时会清理历史遗留的片段独立记录（旧版本曾把 CD2/CD3 单独入库的情况）。
- `GET /Videos/{id}/AdditionalParts` 返回各分段；分段 Id 为 `part-<影片id>-<段号>`，可直接 `PlaybackInfo`/`stream` 302 播放。
- 只存在 CD2、无 CD1 时按普通单片处理，不猜测主片。

### 合集（BoxSet）

读 NFO `<set><name>` 自动聚合。Views 会出现「合集」媒体库（`CollectionType=boxsets`），合集内类型筛选只显示该合集数量≥1 的类型。

## Web 管理后台

`http://127.0.0.1:18080/admin` 提供：
- 总览统计、媒体库管理（可删除库索引）、扫描/重建索引（带实时进度）
- 媒体墙（海报墙 + 无限滚动 + 在线播放；状态/协议筛选、搜索、排序、重读源、删索引）
- 手动补录（http(s) 直链 + 字段 → 生成 strm/NFO 即时入库）
- API 密钥（创建后可直接调用 Emby 接口）
- 任务日志、未知接口探针、设置

后台为响应式布局，桌面 / 平板 / 手机自适应：窄屏（≤860px）侧栏折叠为顶部横向滚动导航、表格与表单自动换行、触屏设备常显卡片操作按钮（无 hover）；播放器按视口限高并适配安全区。

### 在线播放

媒体墙点击海报即在内置播放器（ArtPlayer，MIT，已随二进制内嵌）中播放：

- 默认走 `/Videos/{id}/stream` 的 **302 直拉**（服务端零带宽）；
- 若后台是 HTTPS 而源站是 HTTP（浏览器混合内容拦截）或跨域/防盗链导致失败，自动回退 `/Videos/{id}/proxy`（服务端透传 Range 代理，**仅网页播放器使用**，Emby 客户端仍走 302）；
- 纯浏览器直连播放、不转码：H.265/MKV 等浏览器不支持的编码可能无法播放，请改用 Emby 客户端。

> 浏览海报墙也可用 **Yamby / iPlay** 等 Emby 客户端连接同一地址。

## Emby 客户端接入

Emby 兼容 API 同时注册在根路径与 `/emby` 前缀下：

```text
服务器地址：http://<host>:18080          # 或 http://<host>:18080/emby
账号/密码：  初始化向导创建的管理员
```

已对齐的浏览主链路：认证 → Views（媒体库 + 合集）→ Latest/Resume/Suggestions → Items（排序/过滤/分页/搜索）→ 详情/图片 → 相似推荐 → PlaybackInfo → `/Videos/{id}/stream`（302 直拉）→ 进度/收藏/评分上报。

### API 密钥

后台「API 密钥」创建后，可用密钥直接调用 Emby API（等价于登录令牌，长期有效）：

```bash
curl -H "X-Emby-Token: <key>" http://<host>:18080/Users/1/Views
# 或 http://<host>:18080/Users/1/Views?api_key=<key>
```

## 配置（config.yaml）

```yaml
port: 18080               # 监听端口
debug: false              # true 时启用 gin 调试 + 脱敏请求头日志（不记录正文）
db_path: "emby-go.db"     # SQLite 文件
server_name: "Emby-go"    # 对外站名
server_id: ""             # 留空自动生成稳定 UUID
redis_addr: "127.0.0.1:6379"   # Redis 必选缓存后端
redis_password: ""
redis_db: 0
server_domains: []        # 前端“服务器域名切换”候选
```

`server_id` 会写入配置文件以保持稳定；`redis_addr` 必填，连接失败将拒绝启动。
