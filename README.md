# Emby-go

一个用 **Go** 重写的、兼容 **Emby API** 的轻量媒体库服务端，面向 **AV / FC2 类 NFO + `.strm` 媒体库**（海报墙浏览走 Emby 客户端）。

- 目录库影片元数据真源 = **NFO**（`<title>/<genre>/<studio>/<actor>/<set>` 等），可通过管理端配置 MetaTube 补全元数据
- 本地目录库可选择“影片”“电视节目”“混合内容”；剧集按剧集 → 季 → 单集浏览，混合库同时展示剧集与影片
- 可添加 PostgreSQL `r18_video` 资料库，在网页浏览影片资料并查看、复制 `article` 磁力；暂不播放、下载或暴露给 Emby 客户端，见 [R18 接入说明](R18-CATALOG.md)
- 媒体只支持 `http(s)://` 的 `.strm`；默认 **302 直拉**，媒体库可单独开启服务端播放代理以透传视频流和 Range 请求。本地字幕可独立加载，可选 FFmpeg 提取内封文本字幕或处理音轨（处理时视频经过服务端）
- 单二进制、单端口，Redis 为必选缓存后端；内置深色 Web 管理后台
- 兼容端点覆盖：认证、媒体库/影片墙、详情、图片、合集(BoxSet)、进度/续播、搜索/过滤等 Emby 客户端浏览主链路

在线动漫获取功能已退役。旧库由你执行 [SQL 脚本](scripts/remove_anime.sql) 清理，步骤及独立归档、图片目录的处理见 [移除说明](CATALOG-REMOVAL.md)。

## 快速开始

演员头像支持 GFriends 与 MetaTube，资料默认保存在数据库同级 `actors/`，可预览并复制导入旧头像。设置、恢复与备份见 [演员资料说明](ACTOR-ASSETS.md)，图片和索引的来源条件见 [第三方数据说明](THIRD-PARTY-DATA.md)。

### 构建

Vue 3 控制台已覆盖媒体墙、详情、播放器、管理、任务与刮削页面。`/`、`/web`、`/admin`、`/web/index.html` 返回 Vue 外壳；前两者认证成功后进入 `/admin`，旧 hash/query 书签仍可恢复。迁移入口 `/admin-vue` 重定向至 `/admin`，保留查询及 fragment。进展及未验项见 [P7 实施记录](vue-migration/P7/progress.md) 和 [Vue 迁移开发计划](frontend-vue-migration-plan.md)。

发行版必须使用 `embedui`，构建机器需要 Go 1.26+（模块指定工具链 **1.27.3**；保留默认 `GOTOOLCHAIN=auto` 可自动下载）、Node **24.14.1** 与 npm **11.11.0**，运行机器不需要 Node/npm：

```bash
npm --prefix frontend ci
npm --prefix frontend run typecheck
npm --prefix frontend run test:unit -- --run
npm --prefix frontend run build
go build -tags embedui -o metatube ./cmd/metatube
```

Linux amd64 部署可直接执行 `bash build.sh`，产物为 `dist/emby-go-linux-amd64`。systemd 服务模板和完整安装、权限、升级说明见 [Linux 部署](deploy/README.md)。Linux systemd 冒烟及回滚尚待隔离 Linux 环境验证。

默认 `go build -o metatube ./cmd/metatube` 用于后端开发，不需要 Node；开发 UI 读取包目录中的 `web_dist` 真实构建产物。缺少资源时上述页面返回 503，业务 API 仍可用。旧 `internal/server/web/`、`web_test/` 暂作冻结比对基线保留，待 Linux 验收后完成移除；正式页面不加载旧脚本。

本地热更新：`npm --prefix frontend run dev`，访问命令显示地址的 `/web/ui/` 路径。Go 默认代理目标为 `http://127.0.0.1:18080`，可通过 `EMBY_DEV_PROXY` 指向隔离测试服务。浏览器同源不同端口的登录状态不共享。`build.sh`、`build.bat` 和 release workflow 会先构建一次 Vue 再嵌入二进制；Vite 只清理 `frontend/dist`，不会清理旧 `web/`。

不连接现有库的预览：`npm --prefix frontend run dev:isolated`，自动建立临时 Go/Redis/媒体目录并打印一次性账号，Ctrl+C 后清理。浏览器集成：设置 `PW_CHANNEL=msedge`（本机 Edge）后执行 `npm --prefix frontend run test:e2e`；默认使用已安装的 Playwright Chromium。测试只访问临时实例。

剧集与混合库预览：`npm --prefix frontend run dev:isolated -- --television`。输出中的 `television.tv`、`television.mixed`、`television.empty` 是本次临时目录；在“媒体库”中按相应类型新增后扫描。夹具包含特别篇、第 1 / 2 / 10 季及混合库影片，播放源也是本机临时服务，不访问现有库。

注意现有 `TestRedisBehavior` 硬编码使用本机 6379 的 DB 15 并清理缓存键。在带真实 Redis 数据的开发机器上使用 `npm --prefix frontend run test:go-regression`，该命令显式排除此项并记录未运行原因，不把它记为通过；完整测试只应在专用环境中运行。

### 运行

```bash
# 默认读取 ./config.yaml；也可用 -c 指定其它配置文件
./metatube
./metatube -c /etc/emby-go/config.yaml
./metatube -version
```

`config.yaml` 属本地私人配置（已在 .gitignore 中，不入库）；首次使用复制示例并修改：

```bash
cp config.example.yaml config.yaml
```

监听端口在配置文件的 `port` 中设置，命令行只负责选择配置文件。浏览器打开 `http://127.0.0.1:<port>` 走初始化向导（创建管理员账号）。初始化后，可在“设置 → 实例配置”中编辑配置并保存，详见 [配置页面说明](SYSTEM-CONFIG.md)。

管理员可在“用户管理”中新增普通用户、重置密码、启用/禁用、删除用户及授权媒体库；新用户默认无媒体库权限。普通用户登录后进入媒体墙，收藏、已看与播放进度按账号隔离，不能进入扫描、配置等维护页面。“我的账号”支持验证当前密码后修改账号信息，顶栏支持退出。升级保留原管理员及其数据，功能边界与 Emby 接口见 [用户与访问权限](ACCOUNT-ACCESS.md)。

### 目录约定

每个条目形如：

```
ABF-018/
├── ABF-018.strm        # 内容为 http(s)://... 一行
├── ABF-018.nfo         # Kodi/Emby 风格元数据
├── poster.jpg          # 可选：主海报（也认 folder.jpg/cover.jpg）
├── thumb.jpg           # 可选：宽图（Thumb，也认 landscape.jpg）
├── fanart.jpg          # 可选：背景图（Backdrop）
└── extrafanart/        # 可选：多张剧照，按数字顺序索引
    ├── fanart1.jpg
    ├── fanart2.jpg
    └── fanart10.jpg
```

扫描只按 NFO 判定元数据状态：有合法 NFO → 已入库并可见于 Emby；无 NFO → 待补录；NFO 损坏 → 保留旧索引并重试。STRM 地址与协议在播放时检查，仅支持有效 HTTP/HTTPS 地址。

#### 本地电视节目与混合内容

新增媒体库时选择“电视节目”或“混合内容”。电视节目库只接受单集 NFO，混合内容库同时接受 `<movie>` 与 `<episodedetails>`；影片库不接收单集。已有影片库不会自动改成混合内容。

```text
Show/
├── tvshow.nfo                 # 可选：<tvshow>，剧名、简介、年份等
├── poster.jpg                 # 可选：剧集海报
├── Specials/
│   ├── Show.S00E01.strm
│   └── Show.S00E01.nfo
└── Season 2/
    ├── poster.jpg             # 可选：季海报
    ├── Show.S02E01.strm
    ├── Show.S02E01.nfo         # <episodedetails>，season=2、episode=1
    └── Show.S02E01-thumb.jpg   # 可选：单集缩略图
```

单集的有效 `<season>` / `<episode>` 优先于文件名；缺少或超出有效范围时可从 `S02E01` 形式推断。季号允许 0（特别篇），集号从 1 开始。存在 `tvshow.nfo` 时据其目录归属剧集；否则识别 `Season N` / `SNN` / `Specials` 目录，并回退到 `<showtitle>` 或目录名。剧集资料 NFO 损坏时保留原索引并重试，不把损坏当作删除。同一媒体库和剧目录下季、集号相同的多个 STRM 会合并成一集；详情页可选播放版本，播放进度记在合并后的剧集上。

单集没有主海报时，同名 `-thumb` / `-landscape` 缩略图（以及既有的目录宽图回退）同时提供为 Emby `Primary` 和 `Thumb`，网页单集列表也支持仅有 `Thumb` 的返回。已有主海报优先，电影、剧集和季的封面规则不变；无需重命名单集图片，图片仍在请求时按需读取，无需重新扫描。

媒体墙默认分层浏览；混合库的影片区不重复展示单集。“全部媒体索引”可平铺检查影片与单集。所选剧集和季写入 URL，详情返回与刷新可恢复；首次进入优先选择正片季，特别篇仍可手动选择。播放及进度复用已有接口，STRM 失效不删除元数据，修复有效 HTTP/HTTPS 地址后无需重扫即可恢复播放。客户端兼容范围与本地验证结果见 [剧集与混合库验证记录](codestable/issues/024-o-ff-television-mixed-validation.md)；真实 Emby 客户端及网络挂载尚未验收。

NFO 的 `<runtime>` 与视频 `<duration>` 兼容纯整数分钟、`94分`、`94分钟`、`94分鐘`、`94 min` / `mins` / `minute` / `minutes`，以及 `1:21:00` 这类 `时:分:秒`（分钟和秒须为两位且小于 60）。读取时保留秒级精度，不改写源 NFO；本服务生成的 NFO 仍写纯整数分钟。无法识别的时长或损坏 XML 仍会报错，扫描保留旧索引并在后续扫描重试。

扫描**不做图片格式转换**，直接引用目录里已有的图片（`webp`/`jpg`/`jpeg`/`png`/`gif`/`tbn`）。媒体库封面优先取**库根目录**下 `poster`→`folder`→`cover`→`default` 任一命名的图片（`cover.webp` 同样适用）；没有则借用库内最近入库影片的宽图/海报。

影片本地图片参考 [Emby 电影图片命名规则](https://emby.media/support/articles/Movie-Naming.html#video-images)：海报支持影片同名图及 `-poster`/`-cover`/`-default`/`-movie`，也认目录公共海报；宽图依次识别影片名 `-thumb`/`-landscape`、`thumb`/`landscape`。背景图识别 `backdrop`/`backdropX`、`fanart`/`fanart-X`、`background`/`background-X`、`art`/`art-X`，以及 `extrafanart/fanartX`（X 为数字）。保留服务生成的影片专属海报和背景图优先级；专属背景图不会混入目录公共背景，但仍包含 `extrafanart`。

多张背景图通过 `BackdropImageTags`、`GET /Items/{id}/Images` 的 `ImageIndex` 及 `GET /Items/{id}/Images/Backdrop/{index}` 提供给客户端，编号从 0 开始；管理端影片详情页也展示剧照网格，可点击查看原图。封面在列表/图片请求时发现，剧照在详情/背景图请求时发现；同目录请求共享短期目录清单缓存。图片与 `extrafanart` 目录的增删只使图片和响应缓存失效，不重读 NFO 或写影片索引。无需通过扫描补齐图片。

`HEAD /Items/{id}/Images/{type}` 及带 `/{index}` 的图片地址与 GET 共用取图、权限和缓存逻辑，只返回响应头、不返回图片正文；同时支持根路径、`/emby` 前缀和全小写路径。图片文件允许匿名读取，有有效凭据时仍检查该用户的媒体库权限。电影与虚拟剧集/季提供 Primary、Thumb、Backdrop 等既有图片类型，未提供 Logo、Banner、Art 的独立图片识别；这些条目的缺失或不支持图片返回 404，不以普通海报冒充。媒体库、合集及虚拟实体沿用原 GET 的封面回退规则。

管理员可在“媒体库 → 影片查重”按已入库番号寻找重复影片，选择全部媒体库（包含跨库重复）或单个媒体库后点击“开始查重”；每行媒体库也有“查重”快捷入口。忽略番号大小写、空格/制表符及 `-`、`_`、`.` 分隔差异，保留前导零和版本后缀，不从标题或文件名猜测番号。空番号与电视节目不参与；同一索引记录的 CD 分段只计一部，有番号的未就绪影片也参与。结果显示重复组数、涉及影片数、多出的副本数，点击“查看位置”后可查看原始番号、媒体库、主文件/分段路径、状态并进入详情，同时自动读取每个副本的主 STRM 与 CD 分段内容。内容按纯文本展示，不访问其中的远程链接；缺失、不可读或非 STRM 文件单独提示，读取失败可重试，收起或翻页取消旧请求，再展开读取磁盘当前内容。只允许媒体库目录内的普通 STRM（单文件最多 64 KiB、每部最多 64 个文件），不缓存包含签名链接的响应；分组和组内影片分别分页。统计及成员查询只读数据库，内容读取只读本地文件，不修改索引或删除文件；磁盘路径或番号变化需要先增量扫描。接口为管理员专用 `GET /api/admin/duplicates`、`/api/admin/duplicates/items?key=...` 与 `/api/admin/duplicates/items/:id/strm?key=...`，遵循媒体库访问范围；分组和成员接口支持 `library_id`、`limit`（1–100）、`offset`，内容接口支持 `library_id` 与 `key`。

查重分组展开后，每部影片旁有“删除此副本”。先在“设置 → AList 远程文件管理”保存 `alist_url` 和有删除权限的 `alist_token`（AList 管理后台 API Token，服务端保存、页面不回显，无需重启）。AList 服务地址须与 STRM 链接的协议、主机、端口和反向代理子路径一致。支持 `/d/`、`/p/`、`/dav/` 链接，按 URL 路径解码定位；签名参数不影响定位，已转为网盘供应商直链的 STRM 无法反推 AList 路径。

删除窗口先列出主影片及 CD 分段对应的本地 STRM、远程文件路径和大小，勾选确认后执行。只读取待删副本及其 CD 分段，按 STRM 中的文件路径调用 AList `fs/get` 获取该文件的信息，不遍历全媒体库 STRM，也不调用 `fs/list` 分页读取远程目录。按用户确认的片源独立前提，不检查其他影片是否共享远程文件。预览在服务端有 60 秒整体超时，页面请求在 65 秒内结束等待并提供重试；配置保存期间立即提示稍后重试。服务端只接受与预览一致的目标，并核对当前本地内容和 AList 返回的文件信息；元数据的实时性取决于 AList 驱动与缓存。远程原文件经 AList 删除成功后再删除本地 STRM 和影片索引，保留 NFO、封面及其他文件，不递归删除目录。删除与扫描、刮削、探测、编辑互斥。分段删除无法跨网盘与本地磁盘实现事务：失败会报告已删除的远程路径，SQLite 的删除进度记录支持重新预览后继续，重启后仍保留进度；超时但远程已删除的情况通过单文件查询的明确不存在响应核验后继续，权限/连接失败不会当作文件消失。接口为管理员专用 `GET /api/admin/duplicates/items/:id/delete-preview?key=...&library_id=...`、`DELETE /api/admin/duplicates/items/:id`（提交预览签名、有效期、分组与范围）；原有 `DELETE /api/admin/items/:id` 仍只删除索引。

查重结果还支持“每组保留规则 → 全量选择多余副本 → 批量删除”：可保留最早/最新加入或主文件完整路径最短/最长的一份，其他副本跨全部结果页自动选中，也可在展开的成员中取消个别勾选。加入时间使用首次入库 `created_at`（不是文件修改时间），路径长度按字符数；规则值相同保留 ID 较小的一份，未知时间排在有效时间之后。全部媒体库可处理跨库重复，单库只在该库内保留/选中；切换范围或规则清空选择，浏览结果翻页保留选择。

全量选择仅查询索引，不读取 NFO/STRM 或调用 AList；确认窗口分页展示待删和保留路径。确认后浏览器队列逐份使用现有 AList 预览/删除接口，现场核验当前 STRM 与远程文件，再删除远程、本地 STRM 和索引。每份刚执行时才生成新的 10 分钟预览签名，避免长队列使用过期预览；待删及保留副本的索引身份、路径、分段、加入时间和媒体库目录由选择签名固定，执行时变化或保留副本消失即拒绝处理该副本，不阻塞其他副本。不会读取保留副本的 STRM，也不恢复已撤销的全库共享引用保护。单份失败记录原因及已删除的远程路径后继续处理后续副本，成功、失败和未处理数分别统计；可分页只看失败清单，失败项不计为删除成功。每轮每份最多尝试一次，失败不会自动循环重试；停止后先确认继续未处理项，全部处理后再次勾选确认可只重新核验并重试失败项，已成功项不重复执行。新预览发现远程文件不存在仍保留本地 STRM 和索引，不会为了继续队列而放宽单份删除核验；单份部分删除恢复沿用既有 SQLite 进度。停止/离开页面不启动下一份，已经发出的当前删除会完成清理记账；需保持页面打开，队列本身不是持久化后台任务，重新进入后应再次查重/选择剩余副本。网络响应丢失时先重新查重确认实际状态。全量选择接口为管理员 `GET /api/admin/duplicates/selection?library_id=...&rule=oldest|newest|shortest|longest`，候选数不限当前页，响应和浏览器保存的是全部轻量候选元数据，界面仅分页渲染；尚未进行超大库容量或真实网盘批量验收。

### 实时监听与局部刷新

服务默认启用媒体库监听，不需要点击扫描。Windows 使用 `ReadDirectoryChangesW` 原生递归通知，避免逐层打开目录句柄导致父目录无法移动；其他平台使用 fsnotify 并自动登记新增子目录。

- 启动服务、添加媒体库或恢复失联目录时，先做一次增量对账，补齐停机期间的变化。
- 正常文件事件默认等待 **1 秒静默期**，同一文件的重复通知合并；连续事件最多等待 **5 秒**便提交一批，防止一直不刷新。
- `.strm` / NFO 变化只刷新对应影片或 CD 分组；海报、背景图、宽图变化只刷新相关图片与响应缓存；目录移入、移出或重命名只处理对应子树，不因单文件更新重新遍历整库。
- NFO 文件事件是显式更新信号，因此即使写入工具保留文件大小和修改时间，相关元数据也会重新读取。扫描期间的新事件继续排队；探测、刮削或手动扫描占用 NFO 通道时保留事件并重试。
- 单条 NFO 读取或解析失败时保留旧索引，继续处理同批其他目录，并在任务和进度中记录失败数；不会自动重放整批事件。失败文件修改后或下次手动/定时扫描时再尝试。任务繁忙、目录遍历或数据库等导致刷新未完成的错误仍保留事件并重试。
- 删除媒体库会停止对应监听，退出服务会释放监听句柄。管理端「任务」页显示「实时局部刷新」，扫描进度接口返回本轮统计。
- 目录不可用或读取失败时保护已有索引。根目录失联后会尝试恢复；事件溢出时重新登记监听并做增量对账，积压超过 4096 个路径时合并为一次增量对账，避免静默漏更新。

### 兼容模式（30 秒轮询）

群晖系统、SMB/NFS 等远程文件系统挂载，以及出现「监控不工作」问题时，可以改用兼容模式，不依赖操作系统文件通知。在设置页选择“兼容模式”并保存即可重建监听；也可在 `config.yaml` 中设置并重启服务：

```yaml
disable_library_monitor: false
library_monitor_mode: polling
```

- `realtime` 为默认实时监听模式；`polling` 为兼容模式，二者择一运行。`disable_library_monitor: true` 会关闭两种模式的自动监控。
- 启动时建立文件树快照并做一次增量对账；随后每 **30 秒**遍历目录，比较相关文件的路径、大小、纳秒修改时间和文件模式。检查串行执行，不重叠运行。
- 检测到差异后复用事件合并、防抖、繁忙重试和局部刷新；未变化时不解析 NFO、不写入影片索引、不刷新缓存。管理端任务显示「兼容模式局部刷新」。
- 文件新增、修改、删除及目录移动、重命名会在后续检查中同步；遍历失败时保留上一次完整快照和已有索引，恢复后继续比较，避免把读取失败当作删除。
- 兼容模式每轮仍需遍历文件树，有额外目录 I/O 和快照内存开销。通常在下个 30 秒检查周期加防抖时间后刷新，实际耗时还受目录规模、远程 I/O 和任务排队影响。两次检查之间发生又撤销的变化，或同时保留大小、修改时间及文件模式的内容替换，无法通过属性比较识别，可手动全量重建。

建议保留 `scan` 计划任务作为停机、挂载异常和漏事件的兜底。远程挂载的属性缓存可能额外延迟变化可见性；兼容模式提高通知兼容性，但不能消除挂载本身的读取或缓存问题。

### 增量扫描与全量重建

- **普通扫描默认增量**：顶部「开始扫描」、媒体库「增量扫描」、`POST /api/admin/scan` 及计划任务 `scan` 都只重新处理新增或变化的影片；`library_id` 可限定媒体库，不传则检查全部媒体库。
- **变化范围**：指纹包含同名 NFO 与 CD 分组的回退 NFO（路径、存在状态、大小、纳秒修改时间、文件模式）；电视节目与混合库另包含所属 `tvshow.nfo`，持久化在 SQLite。遍历 `.strm` 名称仍识别影片/分段新增、删除、移动；分段列表单独比较，STRM 内容和图片不参与指纹。
- **首次建立基线**：指纹格式升级为 `nfo-v3`，升级后的第一次扫描会处理现有条目以建立新指纹，以后未变化项不重读 NFO、不重写影片/演员索引，也不改变影片更新时间；完全无变化时不刷新列表缓存版本。
- **删除与故障**：成功扫描后同步清理磁盘上已删除/移动的源文件索引。媒体库根目录不可用或目录遍历失败时停止扫描、不清理；NFO 无法解析或 NFO 不可读时保留旧索引、不写入本轮指纹并跳过本轮删除清理，后续扫描继续重试。NFO 文件不存在仍按「待补录」处理，与解析失败区分开。
- **取消与阶段进度**：扫描进度带 `phase` 字段——`walk` 表示正在遍历目录（`total` 为已发现的候选数），`process` 表示已在处理（`total`/`done` 为本轮候选总数与已完成数）。手动扫描跟随请求 context：客户端断开（关闭或刷新页面）即中止遍历；计划任务、监听刷新随服务停机或监听关闭中止。取消时已提交的批次保留、按磁盘现状的删除阶段不执行，任务记录与计划任务上次结果使用 `cancelled`，管理端显示「已取消」，日志按取消记录而不是失败。
- **全量重建保留**：总览「全量重建索引」、`POST /api/admin/reindex` 和计划任务 `reindex` 强制重读全部媒体库，忽略旧指纹，并重新建立基线；不需要先删库。
- **进度与结果**：返回并展示 `added`（新增）、`updated`（更新）、`skipped`（未变化）、`deleted`（删除）及 `failed`（失败）。`success` 表示 NFO 元数据已入库，`pending` 表示缺少 NFO，均不包含跳过项；扫描不再读取 STRM 判定协议，保留的 `incompatible` 字段通常为 0。播放接口实时读取当前 STRM，仅允许有效 HTTP/HTTPS 地址，失效、空文件或不支持的协议会拒绝播放；替换 STRM 无需重扫。

手动／定时增量扫描仍会遍历目录并检查 NFO 属性，与实时监听触发的局部刷新不同。如果文件变化没有产生监听事件，且外部工具同时保留了文件大小和修改时间，属性指纹不能识别这种内容替换，请执行全量重建。

### 扫描性能与写入安全

- 扫描按最多 **100 部影片一批**写入 SQLite；批次内影片、演员关系、相似特征和扫描指纹一起提交，特征只计算一次。批次失败会整体回滚，未提交条目不会计入新增／更新成功数。
- NFO 读取和解析在数据库事务外进行，最多 **8 路并行**，结果按原扫描顺序分批写库；准备中的条目数量有上限，慢文件不会造成结果无限积压。失败或取消时停止派发任务，并等待后台处理退出后返回；批次等待超过约 **500 毫秒**时，在后续变更条目处理完成后提前提交。该间隔不是远程文件读取的超时时间。
- 扫描不再读取 STRM 内容、取得 STRM 完整属性或选取本地图片；未变化的普通影片只查询一次 NFO 属性，CD 影片另查询回退 NFO。`extrafanart` 目录不参与扫描遍历。
- NFO 文件事件强制局部重读，保留大小/时间的修改也能生效；STRM 事件只增量核对元数据指纹和分段成员；图片事件只刷新缓存。局部指纹查询按源文件前缀缩小返回范围，Unicode 文件名和大批量事件回退目录查询，保留 CD 删除与主段切换语义。
- 批次按姓名合并演员资料，每名演员只更新一次，最后出现的非空头像地址生效，空地址保留已有头像；演员关系不变时不重建关系。相似特征直接从已解析元数据生成，复用批次语句，每条 SQL 最多插入 128 个特征；与普通更新共用规则，特征不变时不重写。
- 目录遍历使用 `WalkDir`，通过目录条目名称识别源文件。NFO 读取前后复核指纹；不稳定条目不保存成功指纹，下次扫描会重新处理。
- 全量重建仍强制重读 NFO，不通过跳过解析伪装提速。数据库使用 WAL，每条连接明确保持 `synchronous=FULL`，不降低已提交事务的持久性。

可用 `go test ./internal/scanner -run '^$' -bench '^BenchmarkLibraryScan$' -benchtime=3x` 比较首次扫描、全量重建和无变化增量扫描，覆盖逐影片目录与单个大目录两种布局。基准使用本地合成文件，不能直接代表 SMB/NFS 的耗时。

电影墙默认可见条目使用全库与单库的标题、入库顺序索引；升级后首次启动自动补建，耗时取决于存量规模。启动及有变化的扫描收尾会通过 `PRAGMA optimize` 更新查询规划统计，不在列表或播放请求中执行。可用 `go test ./internal/store -run '^$' -bench 'BenchmarkScannedMovieBatch|BenchmarkMovieWallSearch' -benchtime=5x -benchmem` 比较批次入库和电影墙 SQL 查询；电影墙默认生成 10 万条主表数据，设置环境变量 `EMBY_BENCH_MOVIES=1000000` 可测百万条。`cold` 强制重新计算总数，`pages` 复用总数；不包含 NFO、图片、HTTP 与浏览器耗时。

类型、标签、厂商筛选使用特征表和 `NOCASE` 索引，保留原有 ASCII 大小写兼容；同一字段的多个值取任一匹配，不同字段共同限定。首次启动自动补建此索引，额外耗时和空间随特征数量增长；相似度计算继续沿用原有区分大小写的特征索引。

#### 用日志判断扫描瓶颈

整库扫描默认记录「扫描性能开始」和「扫描性能汇总」，每次调用以 `scan_id` 和 `library_id` 关联；进入已有指纹查询、影片处理、删除清理时记录「扫描性能阶段」（`index`、`process`、`cleanup`），遍历和影片处理循环约每 5 秒记录「扫描性能进展」。日志同时输出到控制台和 `log/app-YYYY-MM-DD.log`。所有 `*_ms` 字段单位为毫秒，汇总值是本轮累计耗时：

| 字段 | 计时范围 |
| --- | --- |
| `total_ms` | 扫描总耗时，包含取消收尾、版本更新 |
| `walk_ms` | 根目录检查、目录遍历和 STRM 名称分组收集 |
| `index_ms` | 读取已有扫描指纹和分段成员 |
| `source_ms` | 读取前的 NFO 属性与元数据指纹生成 |
| `prepare_ms` | NFO 读取解析、元数据转换 |
| `nfo_read_ms` | NFO 文件打开、读取及关闭（`os.ReadFile`），含失败及 CD 回退读取 |
| `nfo_parse_ms` | XML 解码（`xml.Unmarshal`），含解析失败 |
| `metadata_ms` | 已解析 NFO 转换成影片字段与演员引用 |
| `nfo_reads` / `nfo_parses` / `nfo_bytes` | 文件读取尝试数 / XML 解析尝试数 / 实际读取字节数，含失败和回退；跳过项不计 |
| `verify_ms` | 读取后 NFO 属性与指纹稳定性复核 |
| `db_ms` / `db_pct` | 所有落库批次的总耗时 / 占扫描总耗时百分比 |
| `db_begin_ms` / `db_prepare_ms` | 获取事务（含可能的连接等待）/ 准备 SQL |
| `db_movie_ms` / `db_actors_ms` / `db_features_ms` / `db_fingerprint_ms` | 影片写入 / 演员及关系维护 / 特征生成与读写 / 指纹写入 |
| `db_commit_ms` | 提交事务，包含数据库在提交中的同步或等待 |
| `cleanup_ms` / `version_ms` | 删除缺失源文件索引 / 发布库缓存版本及有变化扫描后的查询统计维护（都可能包含数据库操作） |
| `other_ms` | 分组排序、进度回调、日志等未单独计时的开销 |

`nfo_read_ms`、`nfo_parse_ms`、`metadata_ms` 是 `prepare_ms` 的子项，三者之外还有少量准备流程开销；`db_*` 明细属于 `db_ms`，均不要重复相加。`batches` 是尝试落库的非空批次数，`slow_batches` 是耗时至少 1 秒的批次数，`max_batch_ms` 是最慢批次；失败的 SQL 和回滚仍计入耗时，新增/更新数只计已提交的影片。取消、单条读取失败、落库失败也会输出最终汇总；无变化的增量扫描通常为 `batches=0 db_ms=0`，但清理及版本操作单独计时。受系统计时精度影响（尤其 Windows），极短步骤可能显示 0；应结合批次数和其他阶段一起看。

先看汇总里占时最大的阶段：`db_pct` 高时，再比较 SQL 各部分与 `db_commit_ms`；`walk_ms`、`source_ms`、`verify_ms` 高时优先看目录和属性 I/O；`prepare_ms` 高时比较 `nfo_read_ms`（文件读取）、`nfo_parse_ms`（XML 解码）、`metadata_ms`（字段转换）：读取占比高时检查挂载盘/网络文件读取；解析占比高时检查 NFO 大小和 XML 处理。读取计时包含文件 API、分配及等待，不能单凭它断言物理磁盘性能。可用 `nfo_read_ms / nfo_reads` 和 `nfo_parse_ms / nfo_parses` 计算平均每次耗时；次数为 0 时无平均值。数据库调用耗时包含可能的锁等待，但 `db_begin_ms`、首条写入或提交慢本身不能证明是写锁竞争。

正常批次详情「扫描落库批次耗时」仅在现有 `debug: true` 配置下输出（修改配置后重启）；至少 1 秒的慢批次在默认级别也输出，同轮最多每 5 秒一条，失败批次始终告警。正常快速局部刷新仅在 debug 下记录开始和汇总，耗时至少 1 秒、取消或失败时默认可见。进展日志在调用返回后的循环检查点输出，单次文件/数据库调用阻塞时不会保证每 5 秒出现一条日志；`RescanOne` 单条重扫不输出这些扫描汇总。

### 缓存范围与统计

- Redis 缓存影片列表、详情、分类、相似影片、媒体库封面及鉴权结果。管理端媒体墙列表缓存 **5 秒**；Emby 列表 **15 秒**、详情 **1 分钟**、分类 **30 秒**、相似影片 **20 秒**。图片缩略图与 NFO 流信息仍使用进程内缓存，避免逐张图片访问 Redis。
- 存储层另有最多 **256 条、30 秒**的列表总数 LRU 缓存，同用户、同权限与筛选条件的翻页和排序复用统计。影片写入、删除、刮削状态与权限变化后重新统计；收藏、已看变化刷新相关用户状态筛选，播放心跳保留总数缓存。此缓存不包含影片结果，也不计入响应缓存命中率。
- 局部更新只推进受影响影片的详情版本和对应媒体库的列表版本；跨库列表、全局分类与相似结果随全局版本更新。整库扫描有变化时保守失效该库的详情及磁盘依赖；无变化扫描保留缓存。共享演员头像和头像目录设置变更会失效共享结果。
- 文件事件按路径或子树失效图片标签、NFO 与缩略图；ImageTag 与 ETag 同时包含修改时间和磁盘版本，即使写入工具保留修改时间，客户端也会重新取图。正在加载的旧响应只能写入旧版本，不能覆盖新缓存。
- 影片收藏、已看与停止播放会刷新相关详情和列表；用户状态与媒体元数据分别计版本，播放心跳只刷新单部详情，保留图片路径缓存，旧详情按 1 分钟 TTL 过期。列表进度按短缓存更新，管理端最多约 5 秒、Emby 列表最多约 15 秒。
- 常见列表、详情、分类、相似影片及封面请求发生同键并发未命中时，共享一次查询和响应生成；失败结果不缓存，等待者可随请求取消退出。合并发生在当前进程内。
- 缓存失效使用版本键；旧响应按 TTL 自然过期，不遍历删除 Redis 键，也不清除登录令牌或 API Key 缓存。响应键按当前进程分区，重启后重新建立响应缓存；SQLite 仍是持久真源。磁盘版本按失效批次单调分配，目录失效覆盖所有后代（包括尚未完成的读请求），有效版本取路径自身、祖先目录和版本基线的最大值。记录超过 5 万条时先淘汰 24 小时内没有再次变化的路径，仍超限则整表重置；任何记录回收都抬高版本基线到已分配版本之上，历史 ImageTag/ETag 不会被重新使用。回收时进程内旧缓存按新基线重新加载。
- 进程内 NFO 流信息缓存按路径保存最新解析结果，命中要求路径、文件 mtime tag 与显式失效版本都没变；容量 2 万条，超出按 LRU 逐条淘汰（不再整表清空，热点条目保留），仅同一路径、同 tag、同版本的并发请求共享一次读盘解析。文件改写或显式失效后，新请求独立读取，旧版本读取完成后不会发布到新版本缓存。读取或解析失败的条目只保留 **30 秒**，NFO 补上或被修好后很快恢复；「NFO 正常但没有 `streamdetails`」按 mtime 长期命中，两者分开处理。
- Redis 访问有明确预算：建连 2 秒，单次命令含 1 次重试共 800 毫秒；失败一律按未命中继续（不阻断请求），计入累计失败并写限流日志（30 秒一次）。
- 管理端设置页显示响应缓存命中率、合并加载次数与真实 Redis 连通性；`GET /api/admin/settings` 的 `cache_stats` 按类别提供 `hits`、`misses`、`loads`、`shared`、`load_errors` 与累计 `load_milliseconds`，`redis_online`/`redis_failures` 来自一次带超时的探活。统计自本次启动开始，不包含进程内图片/NFO 缓存。

### 刮削与编辑安全

- 刮削番号精确匹配统一规范标准 `PREFIX-NUMBER`：去首尾空白、转大写，去掉字母前可明确识别的数字厂商前缀，数字末段去多余前导零后补足至少三位。例如 `AEGE-0015` / `AEGE-015` 都为 `AEGE-015`，`109IENFH-29503` 为 `IENFH-29503`。预览推荐、批量/定时选结果及新刮削写入的 NFO 番号/标题采用同一核心规则；保留既有分隔符、明确无横杠格式与 MOSAIC 来源后缀兼容，未知特殊格式不猜数字边界。不同数字和未知版本后缀不会因本规则合并；搜索词仍保留原番号，已有文件名和库内元数据不会被批量重写。本次不改变查重删除的分组规则。
- 新刮削及上传的图片使用影片文件名前缀，如 `ABF-018-poster.webp`、`ABF-018-fanart.webp`、`ABF-018-landscape.webp`。图片请求优先使用影片专属图，旧的目录公共图继续作为回退；只补缺失模式保留已有图片。
- 刮削配置可独立勾选“下载全部剧照到本地”和“下载 MP4 预告片到本地”（默认关闭），对单条、批量及定时任务生效。剧照来自 MetaTube `preview_images`，按来源顺序保存为 `影片名-fanart1.webp`、`影片名-fanart2.webp` 等，详情页和 Emby Backdrop 接口按数字顺序展示；同目录多影片互不串图。预告片来自 `preview_video_url`，保存为 `影片名-trailer.mp4`，详情页优先播放本地副本，支持 Range/HEAD；NFO 同时保留远程预告片地址。仅有 HLS 时仍可在线播放，本期不合并下载 HLS 分片。下载失败显示警告并保留已完成文件；重试仅补缺失，强制覆盖时才替换已有文件，取消/失败不会用临时视频覆盖旧文件。单张图片上限 32 MiB，单个预告片上限 512 MiB、下载超时至少 10 分钟。给已有元数据的影片补资源时，需取消“仅处理缺失元数据的影片”。
- MetaTube 仅需配置服务地址；未启用鉴权的后端可保持 Token 为空。剧照和预告片由 Emby-go 请求源站，不经过浏览器；DMM 请求带 Referer，网络访问沿用进程的 `HTTP_PROXY`、`HTTPS_PROXY`、`NO_PROXY` 环境变量，内网 MetaTube 地址应加入 `NO_PROXY`。
- 批量刮削、扫描、探测、头像任务及单条补录/编辑/重读/上传/探测共用互斥通道。占用期间其他修改返回 409；同类型的独立请求也不能重入。
- 批量刮削取消或熔断后，仍会在释放通道前刷新成功落盘的影片，按媒体库及目录合并局部刷新。影片按批取回，媒体库信息复用，刷新前后各统一失效一次去重的磁盘路径，包含新旧图片依赖；刷新失败与原始任务错误一起返回。
- 请求日志隐藏 URL 和头中的令牌、API Key、Cookie 等凭据；debug 记录脱敏请求头，不记录请求正文，不影响实际鉴权与参数读取。
- 刮削取详情失败时最多依次尝试 3 个精确匹配来源；搜索/详情请求的网络故障、鉴权失败、限流或网关/服务不可用累计触发环境熔断。单条不存在、元数据不完整、解析或本地写入失败不会误触发；取消/请求超时保留原处理。并发进度回调按完成顺序串行发布，取消后已写图片仍会刷新缓存，已提交的 NFO 会完成索引发布。
- NFO 修改按规范化路径串行；元数据更新只处理根节点的直接字段，保留同名的扩展节点、技术信息与未知内容。尊重 `lockdata` 和字段级 `lockedfields`；管理员显式编辑可覆盖锁。图片解码前检查尺寸，上限为 5000 万像素。

### 运维接口与备份

- `GET /api/version` 返回实际构建的版本、提交号和构建时间；未注入版本信息的开发构建返回 `dev`。
- 管理员可调用 `GET /api/admin/metrics` 查看运行时间、内存、协程、索引数量与缓存统计；`GET /api/admin/logs?limit=200` 查看最近至多 500 条应用运行日志。接口不读取任意磁盘文件，普通账号无权访问。现有 Vue 页面未增加这两个面板。
- `log_retention_days` 控制 `log/` 中 `app-YYYY-MM-DD.log`、`request-YYYY-MM-DD.log` 的保留天数，范围 0–3650，默认 **0（不自动删除）**，重启生效。大于 0 时启动与每日首次写入会清理窗口外的已识别日志，跳过当前打开文件、符号链接和其他文件；清理失败不会阻断正常日志。
- 登录失败按直连 IP（20 次/10 分钟）及账号（10 次/15 分钟）限流，触发时返回 429 和 `Retry-After`。通用请求体上限 1 MiB，图片上传 32 MiB。反向代理后的 IP 限流按直连代理地址计算；账号限流仍独立生效。
- SQLite 中持久会话改存 SHA-256 摘要。首次启动以事务迁移原有会话，保留客户端令牌、用户归属、创建时间与撤销规则，失败会回滚并拒绝启动。会话期限和 API Key 界面保持现有约定；**回退旧版时，旧版无法校验这些摘要化会话，需要重新登录**。升级前请保存数据库备份。

可手动运行备份工具，或由系统计划任务定期调用：

```bash
go run ./cmd/embybackup -db /data/emby-go.db -out /backups/emby-go -retain 7
```

备份先生成并校验 SQLite 一致性快照，再复制该快照登记的媒体库 NFO，完整后以 UTC 时间戳目录发布。相同秒的已有备份拒绝覆盖；输出目录位于媒体库中时会排除自身，保留策略仅删除本工具带有效清单的备份。`-retain 0` 禁用清理，`-nfo=false` 只备份数据库。已移除/不存在的媒体库会跳过；NFO 是复制期间各文件的内容，**不构成整个文件系统的同一时点快照**。工具不包含演员图片、配置、STRM、视频或 `mediainfo.json`，这些仍应随部署单独备份。恢复前停止服务，保留原数据库，并清理/隔离旧 SQLite WAL/SHM 后再替换数据库；按媒体库原路径人工核对和恢复 NFO。

本次上游提交筛选、取舍与逐项来源见 [上游审核记录](UPSTREAM-REVIEW.md)。

### 多分段（CD1/CD2）

同目录、同文件基名、末尾带 `-CD<数字>` 的 `.strm` 会被归为**一部逻辑影片**（对齐 Emby stacking 语义）：

```
Split/
├── Split-CD1.strm      # 主段（必须存在 CD1）
├── Split-CD1.nfo       # 主段 NFO 为元数据真源
├── Split-CD2.strm      # CD2+ 作为 AdditionalParts
└── Split-CD3.strm
```

- CD1 作为主影片进列表，`PartCount=CD 数`；CD2/CD3…（任意段数）不重复占列表位。
- 重扫时会清理历史遗留的片段独立记录（旧版本曾把 CD2/CD3 单独入库的情况）。
- `GET /Videos/{id}/AdditionalParts` 返回各分段；分段 Id 为 `part-<影片id>-<段号>`，可直接 `PlaybackInfo`/`stream` 302 播放。
- 只存在 CD2、无 CD1 时按普通单片处理，不猜测主片。

### 合集（BoxSet）

读 NFO `<set><name>` 自动聚合。Views 会出现「合集」媒体库（`CollectionType=boxsets`），合集内类型筛选只显示该合集数量≥1 的类型。

### 客户端筛选、用户和媒体库接口

- `GET /Tags`、`/Years`、`/OfficialRatings`、`/Studios` 返回 `Items`、`TotalRecordCount`、`StartIndex`；从可见影片索引聚合，不读取源媒体或 NFO。支持 `UserId`、媒体库/合集 `ParentId`、`IncludeItemTypes`、`ExcludeItemTypes`、`MediaTypes`、搜索及名称范围、升降序和分页（每页最多 1000）。这些接口目前按上述条件筛选，不支持 Emby 的全部高级查询参数。
- 标签和年份使用 `{Name, Id}`，分级使用 `{Name}`，制片商使用 Studio 项；标签/制片商 ID 与影片列表筛选共用。影片列表支持 `OfficialRatings`（多个值用 `|` 或逗号分隔），与年份、标签、制片商筛选组合，并参与响应缓存键。
- `GET /Users` 返回当前管理员的 UserDto 数组，需要访问令牌；支持 `IsHidden`、`IsDisabled`、`IsGuest`。`POST /Users/{uid}/Authenticate` 接收 JSON 或表单 `Pw`，校验密码并返回登录令牌；用户 ID 使用本服务返回的 `1`，不接受其它 Emby 服务器的旧用户 ID。
- `GET /Library/VirtualFolders` 返回实际配置的媒体库数组，含 `Name`、`Locations`、`ItemId`、`Id`、`CollectionType`、`LibraryOptions`。库 ID 与 Views 一致；自动生成的合集视图不作为实际配置目录返回。
- `GET /Library/VirtualFolders/Query` 返回同一批配置目录的分页对象，包含 `Items`、`TotalRecordCount`、`StartIndex`，支持 `StartIndex`、`Limit`；空页返回 `Items: []`。
- `GET /Library/MediaFolders` 返回当前用户可访问、已启用媒体库的 `CollectionFolder` 项，包含 `Items`、`TotalRecordCount`；库 ID、类型和封面与 Views 一致，不包含自动生成的合集视图，也不返回 VirtualFolders 的目录配置结构。当前没有隐藏库模型，`IsHidden=true` 返回空列表，不将禁用库作为隐藏库暴露。
- `GET /Users/{uid}/Items/{id}/SpecialFeatures` 校验当前用户、媒体库权限和条目存在性；有效电影、单集、分段及虚拟剧集/季返回 `[]`，表示当前未提供花絮。未知、不可见或越权条目返回 404；不新增花絮扫描、关联或播放功能，Season 0 特别篇仍通过原电视节目层级浏览。
- `GET /Persons` 返回可见影片关联的演员 Person 项，使用现有演员 ID；支持上述媒体库/合集范围、搜索、名称范围、排序和分页。图片优先使用本地演员头像，没有头像时回退到参演影片海报；`EnableImages=false` 可关闭图片标识。演员名来自 SQLite 索引，暂不支持导演等其它人物类型或全部 Emby 高级查询参数。
- `GET /Items/{id}/ThumbnailSet` 返回 `{AspectRatio: 0, Thumbnails: []}`；当前未生成播放进度预览帧，空集合表示无预览。它与海报缩略图、剧照无关，也不会触发下载或抽帧。未知或不可见影片返回 404。
- 上述接口同时提供根路径、`/emby` 前缀和全小写路径；除密码登录外均需鉴权。

## Web 管理后台

`http://127.0.0.1:18080/admin`（也可访问 `/web/index.html`，返回相同控制台 HTML，页面登录后使用）提供：
- 总览统计、媒体库管理（可删除库索引）、扫描/重建索引（带实时进度）
- 媒体墙（海报墙 + 无限滚动 + 在线播放；状态/协议筛选、搜索、排序、重读源、删索引）
- 影片详情页（`/admin#item/<id>`，可直链/刷新/浏览器前进后退）：背景图 hero + 播放/探测/刮削/重读源，简介、剧照、演员、相似影片、媒体信息（ffprobe 流信息）、元数据与文件路径分区；点演员/类型/厂商/标签/合集可带该筛选跳回媒体墙（标签同时以芯片显示在标题旁）
- 预告片与远程封面：NFO 里的预告片地址（`uniqueid type="trailerurl"`、`<trailerurlid>` 或其它工具常用的 `<trailer>`）显示在独立的预告片区，点击用内置播放器播放；预告片统一经 `/Videos/{id}/trailer` 由 Emby-go 代理，支持 Range 和 DMM Referer；无剧照时回退背景图、海报或 NFO `<cover>`，剧照网格独立显示并保留原图链接
- 媒体墙返回时先恢复最近一次同条件的列表、计数、滚动位置和影片焦点；超过 60 秒或元数据变更后在后台按原数量更新，取齐后一次替换，不清零重新展示加载过程。播放进度、已看和收藏状态直接更新对应卡片，收藏筛选成员变化仍刷新列表；更新失败保留原列表、停止自动翻页并支持手动重试。切换筛选或账号不复用旧快照
- 切页取消过期读取，防止旧响应覆盖新页面；相似影片独立加载，5 秒超时不影响详情。重读源、探测或刮削后的刷新保留简介与文件信息展开状态；刷新失败保留原页面
- 本地海报、剧照和预告片封面按展示尺寸请求缩略图，并携带图片版本标签；坏图只尝试一次备用封面，仍失败则显示固定尺寸占位。播放错误区分网络、解码、格式与 HTTP 混合内容限制
- 手动补录（http(s) 直链 + 字段 → 生成 strm/NFO 即时入库）
- API 密钥（创建后可直接调用 Emby 接口）
- 任务日志、未知接口探针、设置

后台为响应式布局，桌面 / 平板 / 手机自适应：窄屏（≤860px）侧栏折叠为顶部横向滚动导航、表格与表单自动换行、触屏设备常显卡片操作按钮（无 hover）；播放器按视口限高并适配安全区。

### 在线播放

媒体墙点击卡片进入影片详情页；海报中央的播放按钮、详情页的「播放」按钮在内置播放器（ArtPlayer，MIT，已随二进制内嵌）中播放：

- 默认走 `/Videos/{id}/stream` 的 **302 直拉**（服务端零带宽）；媒体库开启「播放代理」后，同一地址改为由 Emby-go 服务端拉取并透传；
- 详情页预告片始终走 `/Videos/{id}/trailer` 服务端代理，不受媒体库播放代理开关影响；
- 未开启媒体库代理时，若后台是 HTTPS 而源站是 HTTP（浏览器混合内容拦截）或跨域/防盗链导致失败，网页播放器自动回退 `/Videos/{id}/proxy`；
- 纯浏览器直连播放、不转码：H.265/MKV 等浏览器不支持的编码可能无法播放，请改用 Emby 客户端。

> 浏览海报墙也可用 **Yamby / iPlay** 等 Emby 客户端连接同一地址。

## Emby 客户端接入

PostgreSQL R18 来源支持媒体库枚举、库内列表/搜索/偏移分页、详情及代理图片的只读浏览；仅展示 `dvd_id` 有值的记录，播放接口仍返回无可用媒体源。网页和 Emby 默认封面共用最大 `320×480` 海报及按需内存/磁盘缓存，剧照只在详情按需加载，不预下载全库图片。磁力在网页详情查看，不支持客户端播放、收藏/进度或跨库聚合搜索。配置方式、支持接口和查询边界见 [R18-CATALOG.md](R18-CATALOG.md)。

Emby 兼容 API 同时注册在根路径与 `/emby` 前缀下：

```text
服务器地址：http://<host>:18080          # 或 http://<host>:18080/emby
账号/密码：  初始化向导创建的管理员
```

已对齐的浏览主链路：认证 → Views（媒体库 + 合集）→ Latest/Resume/Suggestions → Items（排序/过滤/分页/搜索）→ 详情/图片 → 相似推荐 → PlaybackInfo → `/Videos/{id}/stream`（302 直拉）→ 进度/收藏/评分上报。

### 收藏

控制台侧栏「收藏」按影片与单集、剧集与季、演员、类型、厂商、标签、合集分类，支持搜索、分页、打开条目和取消收藏。影片详情、演员列表、电视节目和实体筛选栏提供心形按钮；媒体墙与演员列表支持「仅收藏」。已绑定且可见的番剧条目也能收藏，未绑定的外部目录不进入 Emby 收藏。

沿用 Emby 的用户收藏接口，`{id}` 使用对应列表或详情返回的 `Id`，当前仍为单管理员 `UserId=1`：

```text
POST   /Users/1/FavoriteItems/{id}         添加收藏
DELETE /Users/1/FavoriteItems/{id}         取消收藏
POST   /Users/1/FavoriteItems/{id}/Delete  取消收藏的兼容入口
GET    /Items?UserId=1&Recursive=true&Filters=IsFavorite&IncludeItemTypes=Movie,Episode
GET    /Persons?UserId=1&IsFavorite=true
GET    /Genres?UserId=1&IsFavorite=true
GET    /Studios?UserId=1&IsFavorite=true
```

以上路由也支持 `/emby` 前缀与小写路径；收藏参数支持 `IsFavorite=true/false`，写入返回 HTTP 200 的 `UserItemDataDto`，包含 `IsFavorite`、`ItemId`、`Key` 和播放状态。条目详情及列表中的 `UserData.IsFavorite` 与写入结果一致。根收藏查询会合并类型、去重番剧媒体别名，再进行排序和分页。

收藏存储在 SQLite：原有影片收藏与播放进度保持不变，非影片实体使用启动时自动创建的 `item_favorites` 表。收藏演员、类型、合集或剧集不会连带收藏其影片或单集，也不会改写 NFO。暂时不可见的实体不列入收藏，原身份重新出现时仍保留收藏状态。API 合约已做本地回归，具体第三方 Emby 客户端仍需实机验收。

### API 密钥

后台「API 密钥」创建后，可用密钥直接调用 Emby API（等价于登录令牌，长期有效）：

```bash
curl -H "X-Emby-Token: <key>" http://<host>:18080/Users/1/Views
# 或 http://<host>:18080/Users/1/Views?api_key=<key>
```

```yaml
redis_password: ""
redis_db: 0
server_domains: []        # 前端“服务器域名切换”候选
```

`server_id` 会写入配置文件以保持稳定；`redis_addr` 必填，连接失败将拒绝启动。

## 开发

```bash
go vet ./...
npm --prefix frontend run test:go-regression
npm --prefix frontend run typecheck
npm --prefix frontend run test:unit -- --run
npm --prefix frontend run test:build
npm --prefix frontend run build
go vet -tags embedui ./...
npm --prefix frontend run test:e2e
```

Vue 回归使用 Vitest/Vue Test Utils 和真实 embedui 服务的 Playwright 场景。Windows PowerShell 设置 `$env:PW_CHANNEL='msedge'` 后运行浏览器测试。大库检查设置 `$env:EMBY_E2E_MEDIA_COUNT='8000'`，只运行 `performance.spec.ts`；常规全套默认使用 307 条夹具，明确跳过大库及未指定旧二进制的回滚场景。冻结旧版的 17 项基线仍可用 `node --test internal/server/web_test/app.test.cjs` 独立比对。

`npm --prefix frontend run test:release` 从当前源码建立不含依赖/生成资源的临时副本，执行 `npm ci` 后生成五平台 embedui 二进制及固定迁移前提交 `5c457893698e74928277d013931f55a2aafb1c84` 的旧版回滚二进制（可用 `EMBY_RELEASE_PREVIOUS_REF` 指定其他基准），结果位于忽略目录 `vue-migration/artifacts/P7/release/`。这是干净源码导出验证；提交后的真实干净检出仍待复验。用 `EMBY_E2E_BINARY` 指定生成的 Windows 发行二进制，`EMBY_E2E_ROLLBACK_BIN` 指定旧版，即可在同一临时数据库中验证回滚。交叉编译不代表 Linux/macOS 已运行。

## 范围与不做

单用户、仅 `http(s)-strm` 媒体库，默认直拉，网页支持 HLS。本地字幕仅在单条详情/播放信息请求中发现，列表与普通扫库不发现字幕。可选 FFmpeg 提取内封文本字幕、重封装多音轨或外挂音频；视频编码保持原样，音频按需转换。不提供通用视频转码、PGS/VobSub 网页烧录、多用户、直播或音乐库。

字幕与音轨的命名、选轨方式、配置和资源限制见 [字幕与音轨](SUBTITLES-AUDIO.md)。
