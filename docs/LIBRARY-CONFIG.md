# 媒体库目录与播放设置

## 一个媒体库使用多个目录

在“媒体库 → 添加媒体库”中填写名称和内容类型，使用“添加目录”登记多个服务器目录，然后保存。已有媒体库可以通过卡片或列表中的“编辑”调整名称、目录和播放设置。

- 一个媒体库内的目录共用内容类型、用户授权、播放设置和浏览入口；一次扫描处理所有目录。
- 重复目录自动合并；不同媒体库不能使用相同或相互包含的目录，避免影片索引归属冲突。
- 同一个库可以填写相互包含的目录，扫描及监控会合并重复遍历范围。
- 目录暂时离线时保留已有索引，并继续处理其他可访问的目录；恢复后重新扫描。
- 从配置中移除目录会清理不再被剩余目录覆盖的影片索引及其播放进度、收藏，保存前会提示确认。磁盘上的 STRM、NFO、图片等文件保留。
- 调整目录时，如果正在扫描、刮削或处理媒体文件，保存会提示稍后重试。

原有单目录媒体库升级后自动作为一个目录显示，库 ID、影片索引、用户授权和播放记录继续保留。增加目录后执行一次增量扫描，即可将新目录的影片加入同一媒体库。

## 播放源请求头

在新增或编辑媒体库时开启“启用播放代理”，即可填写 `Referer`、`Origin`，或使用“添加请求头”填写 `User-Agent` 等附加字段。例如：

```text
Referer: https://example.com/watch/
Origin: https://example.com
User-Agent: MyPlayer/1.0
```

这些字段由 Emby-go 拉取上游视频时发送。填写源站要求的值后保存，重新播放即可使用。留空清除对应自定义请求头；关闭代理时保留配置，重新开启后继续使用。

配置作用于普通视频的 GET、HEAD、Range 请求，以及 HLS 主清单、子清单、分片、初始化片段和密钥请求。使用 FFmpeg 处理音轨或提取内封字幕、使用 ffprobe 探测代理库媒体时，也通过统一代理回源。

启用代理时，内置播放器和外部播放器都使用本服务的播放地址；同时开启“解析直链”时，播放代理优先。需要源请求头的链接应保持代理开启，浏览器直接请求源地址时无法代替服务器发送这些配置。

请求头配置仅管理员可读取和修改，不放入浏览接口或 `RequiredHttpHeaders`。`Referer`、`Origin` 可以随重定向及 HLS 资源转发到 CDN；`Cookie`、`Authorization` 和令牌类字段仅发送至原始 STRM 地址的同源资源，跨源时移除。

请求头名称不区分大小写，同名字段必须合并成一项；名称和值不能包含换行或控制字符。最多 32 项，单个值最多 8 KiB，总大小最多 32 KiB。`Host`、`Content-Length`、`Range`、连接控制字段及本服务鉴权字段由代理管理，不能覆盖。

NFO 预告片仍使用独立代理及原有来源规则，不继承媒体库的正片请求头配置。

## 管理接口

新增目录媒体库使用 `POST /api/admin/libraries`：

```json
{
  "Name": "电影",
  "Paths": ["/media/movies", "/mnt/archive/movies"],
  "Type": "movies",
  "ProxyEnabled": true,
  "ResolveRedirects": false,
  "ProxyHeaders": {
    "Referer": "https://example.com/watch/",
    "Origin": "https://example.com"
  }
}
```

响应中的 `Paths` 是完整目录列表，`Path` 保留为首个目录，旧单 `Path` 调用仍可使用。媒体库类型可选 `movies`、`tvshows`、`mixed`。

编辑使用 `PUT /api/admin/libraries/{id}`，必须带上最近读取的 `Revision`。只提供需要修改的字段，未提供的设置保持原值：

```json
{
  "Revision": 3,
  "ProxyHeaders": {
    "Referer": "https://example.com/updated/",
    "Origin": "https://example.com"
  }
}
```

`ProxyHeaders` 整体替换当前自定义头，传 `{}` 清空。`Paths` 整体替换目录列表，至少保留一个目录。名称、目录及播放设置均可编辑，内容类型在建库时确定。

另一个页面或请求已经修改媒体库时返回 `409`，刷新并核对当前配置后再保存。媒体库编辑界面会保留当前草稿并提示核对。
