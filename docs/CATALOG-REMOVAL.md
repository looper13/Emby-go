# 在线动漫功能移除

更新后的程序不再提供 Bangumi 全量归档、资料补充、TMDB 剧照或 Mikan 发布资源功能，相关页面、API 和计划任务全部退役。本地 NFO 影片、电视节目及混合媒体库继续使用原来的数据和播放接口。

## 主数据库

由你手动执行 [SQLite 清理脚本](../scripts/remove_anime.sql)。程序检测到旧动漫结构时会拒绝启动并提示脚本路径，不会自动删除数据库内容。脚本在事务内清理以下内容，并写入迁移版本 5：

- 12 张 `anime_*` 专用表，包括主体、章节、发布资源、媒体绑定、来源、同步状态和 TMDB 配置及映射。
- `anime.*` 设置、`anime_archive` / `anime_sync` 计划任务、`anime-*` 虚拟收藏。
- 内置动漫库及其专属授权和版本缓存；移除媒体库表的 `system_key`，恢复目录为必填。

普通媒体库的 ID、类型、修订号、代理开关及授权保留。原始 `movies`、`userdata` 和其他收藏不作删除，之前与动漫条目绑定的媒体仍按原 `movie_id` 浏览和播放。

迁移保留媒体库自增序号，避免新库复用退役身份；提交前检查外键和数据库完整性。内置动漫库如果意外含有原始媒体，迁移会回滚并报错，便于核查异常数据。

### 执行方法

停止旧服务并备份主数据库后，在项目根目录运行下面的命令，将数据库路径替换为实际路径：

```bash
sqlite3 -bail "/实际路径/emby-go.db" ".read scripts/remove_anime.sql"
```

`-bail` 必须保留，确保出错立即停止并回滚未提交事务。使用数据库图形工具时，应在同一连接中逐条执行整个脚本，并启用遇错停止；不要让工具自动包裹外层事务，因为关闭外键必须发生在事务开始之前。

脚本适用于已带动漫功能的当前主库，也可对清理后的数据库重复执行。没有动漫结构的早期数据库由新版补齐普通库字段，无需执行此脚本。脚本完成后显示清理成功，最后的 `integrity_check` 应为 `ok`，`foreign_key_check` 不应返回记录，再启动新版。

## 独立运行资料

主库迁移不会自行删除数据库之外的运行文件。确认实际数据库和配置文件路径后，清理范围还包括：

- 数据库同级的 `anime-catalog/`：独立归档 SQLite、目录快照及下载归档。
- 数据库同级的 `anime-images/`：图片索引 SQLite、缓存图片和附属 WAL / SHM。
- 配置文件同级的 `anime-tmdb.local.yaml`，以及已停用的 `tmdb_api_key` 配置项。

这些目录和文件由你另行清理；SQL 只处理主数据库，无法删除磁盘图片和归档文件。普通媒体目录和演员图片目录不包含在删除范围内。

## 验证

自动测试使用临时数据库，执行实际 SQL 脚本，覆盖新库无动漫表、旧库清理后媒体与观看状态及授权保留、脚本重复执行与重复启动、自增序号保留、早期数据库升级、启动不得自动删旧数据，以及异常媒体导致整笔回滚。服务端回归覆盖旧接口返回 404 和退役任务无法新建。
