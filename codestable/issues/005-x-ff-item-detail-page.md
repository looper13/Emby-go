管理端影片详情原是右侧抽屉（`min(560px,100%)`），塞进 11 张剧照网格、演员表、分片与流信息后过于拥挤，且打开抽屉不写历史，浏览器返回键会直接离开页面。改为真实页面 `#item/<id>`：卡片点击即进入，区块按 Emby 详情页组织为 hero（背景图 + 海报 + 标题/徽章 + 播放/探测/刮削/重读源）→ 简介 → 剧照 → 演员 → 相似影片 → 媒体信息 → 元数据 → 文件与时间（默认折叠）。相似影片复用已有 `GET /Items/:id/Similar`，超过 260 字的简介折叠为 6 行。返回按钮与浏览器返回键都回到媒体墙并恢复离开时的滚动位置；直接打开详情链接或在详情页刷新时，返回按钮停在控制台而不是 `history.back()`。快捷播放由「铺满整张海报的透明按钮」改为海报中央 62px 圆钮——原实现会吞掉「点卡片进详情」的点击。

标签（NFO `<tag>`）此前只在元数据区有一行，且点击是静默失效：`adminItems` 本来就读 `tag` 参数、SQL 也按 `tags LIKE '%"标签"%'` 过滤，但前端实体跳转的 `ENTITY_PARAMS` 少了 `tag`，写进 URL 的参数没有任何调用方消费。现将 `tag` 补入实体跳转，并把标签以芯片（`#标签`）显示在 hero 标题旁，点芯片或元数据里的标签都跳到媒体墙并按该标签过滤；同时修正实体跳转直接调 `pageItems()` 导致顶栏仍停留影片标题的问题（抽屉时代不可见，详情改为独立页面后暴露）。

- 改动：`internal/server/web/{app.js,style.css,index.html}` 与 README；无后端改动、无新依赖、无数据库变更（标签解析与筛选本就在后端）。
- 验证：`node --check` 通过；`go test ./... -skip '^Test(MediaProbe|ProbeCircuitBreaker)$'` 全绿（一次运行中 `internal/nfo` 的 `TestSaveStreamDetailsInsertsWithoutFileInfo` 出现已记录的 Windows 重命名抖动，单独重跑 3 次全过）。真实实例浏览器走查（本机 Redis、临时库、夹具库 23 部影片，标签 单体=2/合集作品=1/批量=20）：卡片标题点击进详情、海报边缘点击进详情（命中测试确认该点不是播放钮）、中央圆钮快捷播放、相似影片进入另一部详情、浏览器返回键回到上一部、返回按钮回媒体墙且滚动位置 778px 精确还原（走查时已置 `history.scrollRestoration='manual'`，证明是代码恢复而非浏览器原生行为）、从已滚动的媒体墙进详情时 hero 从顶部可见、直接打开 `#item/2` 后返回仍停在 `/admin`、简介展开/收起、文件与时间折叠；标签链路单独验证：hero 芯片显示 `#单体`/`#高清`、点芯片跳到 `?tag=单体` 且媒体墙只剩该标签的 2 部、筛选芯片与计数文案正确、✕ 清除后回到 23 部、元数据里的标签按钮走同一条路径，顶栏标题在跳转后为「媒体墙」。首屏与下半屏截图复核版式符合确认过的线框。
- 验证限制：移动端断点（≤720px）只按 CSS 规则核对，未实机截图；Playwright 的可操作性点击在本轮出现 4 次 3 秒超时（跨登录页、深链详情页、媒体墙筛选栏），命中测试显示目标按钮均未被遮挡、同批次其它点击正常，且其中登录页不在本次改动范围内，故按自动化层问题处理，这些路径改用页面内派发 click 验证；未用真实 Emby 客户端复验图片/详情契约。原 CSS 注释引用的「需求 R3b」原文在 gitignore 的 `docs/` 中、本地不存在，移动端全宽行为按等价方式保留并改写了该注释。
- codestable：无 spec/epic 需同步（当前工作区只有 issues 树）；README 已同步详情页、标签筛选与播放入口描述。「已看/收藏」开关未做——管理端此前没有该能力，属新增功能，本次范围外。
