# 115 大账号离线排队与提交协议修复

用户提供 Cookie 和一条磁力，反馈本地任务一直显示排队。承接 [058](058-o-r18-115-offline-playback.md)，本地修复与真实账号测试完成后等待用户环境验收；不自动提交、推送、部署或关闭事项。

- 根因一：首次对账扫描未过滤的全部离线历史。实测账号当时有 5141 条任务，默认每页 30 条、共 172 页，超过代码的 100 页上限；逐请求限流期间页面一直显示 queued。115 的 `info_hash` 筛选区分大小写，大写查询会遗漏已有任务。
- 修复一：`internal/cloud115/cookie.go` 的 `Find` 统一小写哈希并服务端按哈希过滤。第一轮按每页 1000 项保留分页回退，用户进一步确认逻辑后收紧为 `page=1&page_size=1` 的单次查询，删除 Cookie 路径的 100 页循环。只接受明确的 0/1 条完整结果，核验页码/数量/任务字段及目标哈希；缺字段、未过滤历史、截断或歧义结果返回可重试错误，不把查询失败当作不存在、不回退扫描历史。保留提交前去重、提交超时/重启后先对账以及既有 1 秒限流；旧 OAuth 兼容分支不在本次修改范围。
- 根因二：`lixianssp` RSA 提交接口不接受通用 `Mozilla/5.0`，不含下载链接的协议探针返回 HTTP 200 / `decode fail!`。分别对比域名、版本、随机密钥与应用 UA 后，确认只补应用 UA 即可得到正常的加密 JSON 响应，Cookie 本身有效。
- 修复二：只为离线提交设置与 `app_ver` 一致的 115 应用 UA，播放直链仍使用真实客户端 UA。补充 `error_msg` 错误字段读取及 Cookie 脱敏，避免上游拒绝时丢失原始原因；不更换 SDK、不绕过去重或缓存目录保护。
- 回归：哈希筛选/大小写回归和提交 UA 回归在旧代码上分别失败；本轮新增的单次查询/异常结果/无效哈希回归也在前一轮分页代码上失败，修复后聚焦 Go 测试连续 3 轮通过。新增队列查询失败不提交、仅从未提交任务可在完整无结果后提交、清理查询失败不删任务/文件及恢复测试；未知提交先对账、取消/到期清理和外部目录保护测试保留。相关包 Go vet、embedui Go 构建通过。
- 实测：先验证既有服务缓存根/子目录身份，重新确认远端没有目标任务后用修复代码提交一次；远端状态从 0/1 到 2，下载进度 100%，结果属于原任务缓存子目录，发现 3 个视频候选。后续只读对账没有再次提交。最大候选约 20.1 GB，直链成功解密、HEAD 为 200，读取前 1024 字节返回 206 和正确 Content-Range；详见 058 最新验证记录。未自动选择/绑定正片，不把接口测试当作网页或原生 Emby 播放验收。
- 本轮只读复测：真实接口接受 `page_size=1`，目标任务返回 count=1/page_count=1，无结果返回 count=0/page_count=0，任务数组明确存在。新代码用大写输入查询原磁力，单次 HTTP 请求确认完成/100%；另查无结果哈希也只发一次请求。探针保留正常限流，无提交、删除或本地业务状态写入。
- 数据边界：Cookie 只在临时探针的标准输入中使用，不写配置、SQLite、源代码或报告；未记录签名 URL，未删除网盘文件，未修改生产任务状态。临时探针和构建检查产物在测试后移除。已有 `.gitignore` / `AGENTS.md` 文档整理修改及 `output/` / `vue-migration/` 删除保持原样，不混入本修复。
