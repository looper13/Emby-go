用户提供的 49,824 条未变化影片扫描日志总耗时 14.161 秒，其中 source_ms=12,370.354、db_ms=0。经讨论确认：扫描指纹只检查 NFO；STRM 内容与有效性在播放时检测；封面随列表/图片请求加载，剧照随详情/背景图请求加载。

- 指纹升级为 nfo-v3，只包含同名与 CD 回退 NFO 的路径、存在状态、大小、纳秒时间和模式。STRM 目录条目名称与数据库分段列表单独对照，保留新增、删除、移动和 CD 主段切换；扫描不读取 STRM 内容或取得 STRM 属性，不遍历 extrafanart。首次升级扫描重建基线，以后未变化影片只查询 NFO 属性。
- NFO 事件强制重读，STRM 事件增量对照分组，图片/extra 目录事件只刷新缓存和内存响应版本，不落库。保留全量重读 NFO、读取前后稳定性复核、损坏元数据重试、取消保留已完成批次及事务原子性。
- 播放直接读取当前 STRM，验证 HTTP/HTTPS 地址并重新解析容器和展示文件名。元数据 success 改为“已入库”；管理端详情返回实时协议和 playable，源不可用不影响元数据索引。播放无效源返回 404，地址变化无需扫描即可生效。
- 图片路径由请求时目录清单解析；列表仅选封面/宽图，不读取 extra 目录。详情解析多张背景图。清单按目录短期缓存、并发合并加载，失效代次阻止旧加载覆盖新数据，限制目录数和图片名称总数。继续保留影片专属图、公共图回退、多图顺序和手动图片回退。图片、详情、合集、实体、媒体库封面接口均接入按需解析；刮削/上传后的失效同时包含旧路径和当前磁盘图片。
- README 与界面说明同步；仓库无 spec/epic 需同步。旧图片指纹测试替换为 NFO 专属依赖、迁移一次、只查询一次 NFO、读取中途修改重试；图片 API 与上传/监听回归改为检查请求结果而非扫描写入图片字段。新增源实时变更、空/不支持源拒绝、图片刷新不读损坏 NFO、封面与剧照按需加载及详情缓存立即更新回归。
- 本机 Windows、同一 BenchmarkLibraryScan 合成 300 部、各模式 3 次：未变化逐影片目录 139.619 → 46.092 ms/op；未变化大目录 76.489 → 17.338 ms/op。首次扫描 282.921 → 191.246 / 522.071 → 344.461 ms/op；全量重建 474.474 → 147.144 / 360.559 → 204.936 ms/op。基线为提交 6a05d67 的源代码，保持同一 SQLite/批次/持久化设置；仅本机合成数据，不代表真实远程挂载提速幅度。
