# 115 完成记录缺失文件时自动重新下载

用户明确要求：找到磁力添加记录后定位实际文件，文件不存在就自动重新添加，不再要求人工恢复文件。承接 [058](058-o-r18-115-offline-playback.md) 与 [059](059-o-ff-115-queue-reconcile.md)，不扩展为无人请求时无限续期、扫描全网盘或删除已有外部文件。

- 文件真相：完成记录先通过结果 `file_id` 核验；明确的对象不存在、完整空结果目录，以及已选择正片被删除会触发恢复。网络、验证/权限错误、未知结果 ID、只有非视频但仍存在文件等情况不当作删除。外部记录若有文件仍不复用、不移除；用户本次要求允许移除已确认结果丢失/为空的完成记录，无论它属于旧缓存还是外部目录，但只移除离线记录（`flag=0`），恢复流程不删除任何云端文件/目录。
- 持久化：`internal/offline/recovery.go` 保存目标文件、旧记录的结果/目录身份与恢复次数，再重查记录和文件；记录或文件状态变化则跟随现存下载，不移除替换记录。仅在确认旧记录已从 115 消失后回到 queued，复用或重建专属缓存子目录，再沿既有 submitting 持久化边界提交一次。移除超时和重启继续对账，已成功移除但仍可见时有限退避，不反复移除/提交。
- 业务状态：播放前发现所选文件已删时只把已授权任务入队，后台恢复；立即清空旧候选和绑定，后续完成后只发布新候选。API 不执行磁力提交，仍按原有条目、媒体库、用户及票据授权验证。取消和版本 CAS 阻止迟到结果复活。
- 缓存期限：恢复保留原始创建时间和绝对到期时间；缓存子目录被删时重新验证命名根目录并重建专属子目录，不延长有效期。已到期任务只清理，不自动续租；用户之后再次提交才开启新周期。每个周期最多自动恢复 3 次，防止上游反复报告缺失导致无限下载。
- 验证范围：聚焦测试覆盖缺失结果、旧缓存/外部空完成记录、空结果目录、所选正片丢失而附件仍在、旧记录已不存在、缓存子目录重建、新文件发布与旧绑定失效；另覆盖网络/权限/非空外部目录、文件恢复、记录替换（包括探测期间）、取消/到期、移除可见性延迟、次数上限。真实 SQLite 关闭重开验证移除超时和新 Add 超时后不重复写入。
- 本地结果：最终聚焦 Go 回归连续 3 轮通过，相关包 Go vet、embedui Go 构建及 diff 检查通过；没有前端代码变更，不把此结果扩大为全仓回归或部署验收。
- 文件：`internal/offline/service.go` / `recovery.go`，`internal/store/cloud115.go` 增加向后兼容 JSON 恢复字段并使待处理状态失效旧绑定，`internal/server/cloud115.go` 入队文件缺失，`internal/cloud115/client.go` 区分空结果目录；对应 Go 回归测试。无需新表/DDL、前端状态或凭证变更。
- 验收边界：没有用用户真实文件制造删除来测试，本分支的缺失/删除/重下证据来自受控 Provider 与真实临时 SQLite，不代表真实 115 删除后重下或完整网页/Emby 播放验收。此前真实磁力下载/直链与单次查询证据仍见 058/059，不混为本次验收。
