- 已实现：管理员点击“查看位置”后，位置先显示，每个副本独立读取主 STRM 与 CD 分段文本；每个文件的内容放在对应路径下。空文件、缺失/不可读/非 STRM 分别提示，整体请求失败或 30 秒超时可重试；收起、切组、翻页及离开页面取消旧请求，再展开读取磁盘现状。等待用户实际验收。
- 当前局部界面（内容只以文本显示，长链接换行，内容区域过长可滚动）：
  ```text
  番号 / 份数 / [查看位置 -> 收起]
    副本标题 / 状态 / [删除此副本]
    媒体库 / 原始番号
    主文件路径 -> STRM 内容或读取提示
    分段路径   -> STRM 内容或读取提示
  ```
- 改动：新增 `internal/server/duplicate_strm.go` 与管理员 `GET /api/admin/duplicates/items/:id/strm?key=...&library_id=...`，复用现有媒体库目录/符号链接范围和普通 STRM 读取护栏，单文件最多 64 KiB、每部最多 64 个文件；`Cache-Control: no-store`。不读取其他副本、不联系 AList、不请求 STRM URL、不写索引或删除进度。前端新增 `DuplicateStrmContents.vue`、查重 API/面板、`library.css` 及回归测试，未改冻结 `legacy.css` 或已有删除流程。
- 验证：后端查重/删除/账号媒体库权限定向测试、store/AList 全套、server Go vet 通过；覆盖主文件/CD、实时重读、空/缺失文件互不影响、权限/分组范围、目录外/非普通文件和体积/分段限制。Windows 无创建符号链接权限，真实符号链接用例跳过，不声称已实测该边界。
- 前端 29 文件 305 项单测、类型检查、生产构建及 embedui 后端构建通过；覆盖按需读取、文本转义、失败/超时重试、收起取消与拒绝旧结果。独立临时媒体库/数据库/配置/Redis 下 Chrome 1280x900、390x844 检查主/CD 内容、单副本缺失提示、长链接不横向溢出；修改/恢复 STRM 后无需扫库，重新展开即看到最新内容。没有浏览器远程资源请求或脚本错误，截图在忽略目录 `output/playwright/duplicate-strm-*.png`。
