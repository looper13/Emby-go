# 独立演员管理页与批量头像入口

用户需要集中管理演员并一键批量补齐头像。原入口位于影片刮削页下方，现新增左侧「演员」入口 `/admin#/actors`；旧刮削页保留引导链接。

- 页面顶部选择全部或单个媒体库，启动该范围内全部演员的头像任务。复用应用级任务锁、进度、取消和恢复；已有头像、非空 NFO thumb 与默认来源策略保持不变。任务完成刷新列表。
- 卡片列表提供姓名、实际本地图状态、范围内参演电影数与作品链接，支持姓名搜索、状态筛选和每页 48 位。列表筛选不改变批量范围；恢复任务可能使实际任务数不同于缺图统计。
- 来源、GFriends 索引、存储路径说明、旧头像导入移到演员页，配置显式保存/恢复。演员和影片表单只提交各自负责的字段，防止旧草稿覆盖另一个页面的设置。
- 新增鉴权只读接口 `GET /api/admin/actors`。影片数由 SQL 聚合，头像状态复用 Person 本地读取缓存；远程地址和影片海报占位不算本地图，孤立历史演员不列出。读取不下载或写入 NFO。
- 修改范围：Vue 路由/侧栏/演员页、来源表单与原刮削页拆分，演员 API、store 聚合、使用说明和回归用例。未修改冻结的旧前端与 CSS。
- 验证：类型检查、前端 16 文件 / 201 项单测、正式生产构建通过；store/actorassets/gfriends/scraper 完整回归、server 演员/鉴权/分页/缓存与 Vue 契约定向用例、Go vet 通过。Edge 桌面/移动端演员与 P5 工作流最终合跑 18 项全部通过（3.2 分钟），覆盖取消、跨页运行、刷新恢复、幂等重试、图片真实加载、媒体墙跳转与无横向溢出。截图已人工检查，保存在忽略目录 `frontend/test-results/actors-page-final`。
- 边界：大规模演员目录首次状态遍历尚未专项测量，外部直接增删文件受现有头像短缓存影响；真实 Emby 客户端与 Linux 实机仍沿用前一阶段未验收项。详情见 [演员说明](../../ACTOR-ASSETS.md)。

本记录保持 open，不自动关闭既有事项。
