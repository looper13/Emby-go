# R18 磁力到 115 离线任务、文件选择与 302 播放

## 目标与边界

承接中断聊天中已确认的流程：管理员在 R18 详情选择 article 资源或手动磁力，创建本地任务，后台向 115 提交和对账，完成后确认视频文件并绑定播放源；网页或 Emby 播放时按实际 User-Agent 获取直链，返回 302。

PostgreSQL 仍为只读资料来源，任务和绑定只写本地 SQLite。不生成 STRM，不扫描整个网盘，不引入 WebDAV/rclone、视频代理或转码；R18 收藏、已看/进度、跨库聚合仍不在本次范围。仅管理员创建和手动操作任务，普通账号按既有媒体库授权播放就绪文件；已授权播放发现文件丢失可以触发原任务后台恢复，不能指定新磁力或延长缓存。2026-10-29 用户明确追加 Cookie-only 配置、统一 `缓存-24h自动删除` 目录及到期自动删除；此前“不自动删除网盘文件”边界被收窄为“只删除本服务创建的任务缓存，不动外部目录或旧任务文件”。同日用户进一步要求文件缺失自动重新下载，允许移除已明确无结果文件的完成记录（仅记录、不删除任何已有文件）；有结果文件或未完成的外部任务仍不修改。

## 当前实现

- `internal/cloud115` 隔离 SDK：BTIH 十六进制/Base32 规范化、逐请求限流、受控刷新并持久化 Token、带取消的客户端串行门、离线列表分页与单项提交错误、目录扫描及直链。明确修正 SDK 的 GET 表单分页和提交单项错误被忽略的问题。
- `internal/store/cloud115.go` 新建连接、任务和 R18 绑定表。账号和 InfoHash 唯一去重，任务更新采用版本 CAS；绑定包含媒体库配置修订，防止源库换库后复用旧条目。重新打开 SQLite 保留凭证、提交中状态和绑定，旧客户端刷新不能覆盖新配置。
- `internal/offline` 独立于 cron 的常驻队列；先查远端再提交，并在远端写之前持久化 `submitting`。提交超时和重启先对账，绝不盲目重复提交。取消阻止旧版本发布结果，本身不删除网盘任务/文件。完成单个视频自动绑定，多个候选待选；凭证失效、有限退避、24 小时等待上限和阶段重试均保留配置及文件身份。2026-10-29 用户追加自动恢复：完成记录的结果文件或已选择正片明确丢失时，持久化旧记录身份、移除失效完成记录并确认消失，再重新提交；不依据网络/权限失败重下，不删除现存云端文件，恢复不延长原缓存期限。
- `internal/server/cloud115.go` 管理员配置/资源核验/文件选择接口、用户可见播放源及 302。源身份、授权、用户启用状态、媒体库修订在每次播放前检查；FileID/SHA1 确认后使用最新 PickCode 与真实 UA 获取 URL。匿名旧本地流行为不变，115 必须有账号认证或 6 小时的条目/来源/用户绑定签名票据，重启票据失效。HEAD 和 302 不传正文，不缓存或记录签名地址。
- 凭证使用 AES-GCM，数据目录 `.115.key` 使用 Unix 0600 / Windows 受保护 DACL；接口不回显凭证，错误和日志脱敏。设置页及保存 API 改为只填 Cookie，验证成功后自动创建/复用命名缓存根目录，无 Token/文件夹输入；当前仅支持同账号更新，不支持切换共享账号。旧加密 Token 保持可解密，既有任务不自动搬动或删除。
- R18 详情的影片信息旁增加版本选择和媒体库同款播放按钮；当前磁力列表置于剧照前，每个规范化 BTIH 为一个版本，相同哈希的重复 article 记录合并，手动提交的磁力也显示。管理员一键完成提交/复用任务、等待、推荐最大视频文件绑定与打开播放器；保留手动正片/默认源和 PotPlayer 入口。自动选择不改变其它版本的默认设置。
- 播放前经授权的 `offline/prepare` 核验实际文件身份；明确缺失时失效旧源并进入已有后台恢复流程，前台继续等待新源，不先打开失效播放器。预检不获取签名 URL，最终媒体流仍按实际客户端 UA 获取直链并 302。页面每 5 秒只读本地状态；切换版本、停止自动播放或离开页面不会取消后台下载，过期任务只能清理后开启新生命周期。刷新失败保留已有内容。设置页 Cookie 为密码框，保存后清空。

## 2026-10-29 增量设计与执行

- Cookie HTTP 适配器隔离在 `internal/cloud115/cookie.go`；保留原 Provider 主接口，缓存写操作通过 CacheProvider 承担。仅引用 `115driver v1.3.5` 的 RSA 编码模块，避免无取消的整套客户端；HTTP 限流、超时、重定向禁止、响应大小限制、混合数字/字符串 ID 和 Cookie 完整值/字段值脱敏在适配器内处理。现场修正离线查询为小写 InfoHash 过滤，后续按用户要求收紧为单次查询/最多一项并核验完整结果，不再分页扫描历史。提交采用应用 UA（普通浏览器 UA 会返回 `decode fail!`），并读取 `error_msg` 保留上游拒绝原因；播放 UA 不变。
- 本地任务增加缓存子目录 ID、绝对到期时间。首次 mkdir 之前持久化清理意图，目录名称由任务 ID 确定，mkdir 超时/取消也能重新定位并清理；提交仍持久化 submitting 后远端写，重启不盲目重提。缓存从开始创建计时 24 小时，重试/播放/取消不续期。
- 清理独立于活动任务轮询，覆盖就绪、失败和取消状态，先持久化 cleanup_pending，使旧 CAS 结果不能复活；核对命名根目录/父子关系/专属子目录名字，停止写入该子目录的远端任务后删除子目录，保留统一根目录、外部同磁力任务和其它文件。错误退避重试并在重启后继续。到期来源列表、文件选择和已有播放票据均立即拒绝，清理完成后重提交可重新下载同一磁力。
- 质量目标：可靠性以真实 SQLite 关闭重开、mkdir/delete 超时、取消/到期清理和重新提交测试验证；信息安全性/数据保护以 Cookie 不回显、到期票据拒绝、目录移动/改名/外部同磁力不删除测试验证；交互能力以 Cookie-only 表单、保存后清空、清理状态/时间提示和桌面/手机浏览器夹具验证。

目标局部界面（沿用原有设置面板与详情位置，不重设计其它区域）：

```text

Cookie [password input]    [Validate and save]
```

## 有界取舍

只保存文件身份，不持久化临时直链；第一版播放时重新获取直链，不增加签名 URL 缓存。旧 OAuth 连接仍使用 SDK 的接口拒绝后刷新，新 Cookie 失效后由管理员更新，不自动获取 Cookie。账号统一至少 1 秒间隔，队列串行处理到期任务，每次读取最多 50 个任务，另有每批最多 50 个缓存清理任务；目录最多 10000 项/16 层。Cookie 对账只按目标 InfoHash 单次查询最多一项，完整性或筛选异常即报错，不扫描全历史、不依据异常结果提交或清理；旧 OAuth 兼容分支保留原有 100 页上限。大量并发离线任务尚未做吞吐量验收；如果队列规模增长导致播放等待或重复列表查询成本显著，应升级账号级任务快照和调度，而非让网页直接访问 115。

旧 `embybackup` 只备份 SQLite/NFO，不包含 `.115.key`；需另行保密备份密钥与 SQLite。用户提供的 Cookie 仅用于本次临时测试，不持久化；接口现场测试不能代替完整网页/Emby 闭环、其它出口 IP/客户端请求头兼容或原生 Yamby 验收。
