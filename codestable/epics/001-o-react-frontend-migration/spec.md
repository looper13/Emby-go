# React 前端迁移与媒体界面重制

## 这条线要改变什么

把 Emby-go 的正式 Web 控制台从 Vue 切换为 React，并在媒体墙、筛选区和影片详情上采用 nowen-video 可观察到的浏览层级与密度。当前产品没有 `codestable/spec/` 或 Vision 文档；本 Epic 以用户本轮要求和现有前端行为为来源，稳定业务事实以现有 Go API、存储与已发布行为为准。

目标入口是 `/web/ui/`。React 承担登录、授权、路由、所有产品页面、播放器和 AVdb 界面；Go API、SQLite/Redis 数据、扫描、媒体播放及服务端凭据边界保持原契约。迁移实施期间保留旧 Vue 测试和源码作为行为对照；当前 Vue-only 入口与模块已退役，原行为清单通过 Issue `002` 继续核对 React 覆盖。

nowen-video 标注 GPL-3.0。只使用公开界面能观察到的布局和交互层级；Emby-go 的组件、CSS 与图片均由本项目独立实现。

## 当前怎么理解

桌面媒体浏览保留全局导航，内容区域按媒体类型、搜索与排序、展开筛选、海报网格的顺序组织。手机将筛选控制纵向排列，媒体网格按可用宽度自适应，并保留底部导航。影片详情以背景 Hero 承载封面、标题、状态与主要动作，正文依次呈现简介、演员、剧照、文件资料、相似影片和 AVdb 社区内容。

稳定边界：

- 现有 hash/query 书签、鉴权与用户隔离、API/DTO、权限控制及危险操作确认保持兼容。
- 筛选、详情、返回恢复用户可观察到的 URL、条数、滚动与焦点状态。
- 页面 GET 可随页面离开取消；写请求与应用级后台任务的生命周期独立于路由。
- AVdb 前端只使用同源 `/api/r18`，服务端密钥不进入浏览器；清单收藏只保存引用。
- 媒体墙、详情与管理页面都要提供加载、空、错误和窄屏布局状态；交互控件保留键盘与可访问名称。
- 保留用户原有筛选结构、可访问状态、选中态和电视视图交互；对应 Vue 文件现已退役，React 行为覆盖的剩余审计由 Issue `002` 跟踪。

## 架构与质量取舍

React 页面复用 `frontend/src/api/` 契约和既有纯逻辑模块；路由页面按需加载，Zustand 持有认证、媒体墙、播放器和后台任务等跨页状态。页面请求 hooks 负责可取消读取，播放器与应用任务有独立生命周期。React 与 Go 的正式集成仍经现有构建发布器和 `/web/ui/` 资源文件系统。

本 Epic 关注：功能正确性与旧 URL/API 兼容、任务和播放资源可靠释放、桌面/移动交互能力，以及删除 Vue 前有足够的可观察回归证据。HLS 保留独立动态 chunk；500 KB 警告是当前已知上限，若构建或设备测量证明其影响目标，再评估额外切分。
